Хранилища

Применимо: 1.26.9WindowsLinuxDocker

Где Оркестратор хранит файлы: дистрибутивы робота и агента, архивы RPA-проектов, скриншоты роботов, keytab. Как подключить S3 (MinIO или Ceph), как включить общие папки и куда пишутся дампы журналов.

Архивы RPA-проектов: RpaProjectArchiveUpload

ПараметрНазначениеПо умолчаниюС версии
RpaProjectArchiveUpload:DbStoretrue — в БД ltools, false — в папке TargetFilePath на сервере WebApitrue
RpaProjectArchiveUpload:StoreType1 — в БД ltools, 2 — в S3. 0 (папка на сервере WebApi) устарел12 — 1.26.9
RpaProjectArchiveUpload:TargetFilePathПапка архивов для устаревшего StoreType=0—
RpaProjectArchiveUpload:FileNameTemplateШаблон имени файла для StoreType=0{0}.zip

StoreType=2 работает, только если в WebApi включён S3: FileStore:Type=1. Иначе загрузка проекта упадёт — заглушка хранилища не реализует запись. Новый тип действует для новых загрузок; уже загруженные версии читаются из того места, куда были сохранены.

При обновлении до 1.26.8 старый параметр DbStore больше не учитывается — удалите его или замените на StoreType.

Как проверить

  1. Перезапустите WebApi и RobotLogs. Службы стартуют без ошибки «Error configuring Minio.Storage».
  2. Загрузите дистрибутив робота и новую версию RPA-проекта. В бакете (или в папке robotdistr/, projectarch/ общего бакета) появились объекты <Id>.zip; проект скачивается из UI4.
  3. Запустите робота, который делает скриншоты. Скриншоты открываются в журнале робота.

Дамп секций журналов в 1.26.9 по коду отключён (обработчики закомментированы, служба LogsDumpService не регистрируется), хотя параметры LogsDump и вкладка «Журналы» остались. Старое руководство требует, чтобы папка дампа была на сервере БД. Подробнее — Обслуживание БД.

При нескольких экземплярах WebApi без S3 каждый узел проверяет наличие файла дистрибутива у себя (событие 1204 при рассогласовании). Нужна ли общая сетевая папка для TargetFilePath, в коде не сказано — уточнить.
