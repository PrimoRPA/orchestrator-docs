Задания и триггеры

Применимо: 1.26.9UI4

Задание связывает RPA-проект с условиями запуска. Условия задаются триггерами: расписание, письмо, папка, очередь, завершение другого проекта.

Часовой пояс расписаний и производственного календаря задаётся параметром WebApi Scheduler:TimeZoneId (с 1.26.7.6; в поставочном конфиге — Russian Standard Time). Не задан — используется пояс ОС сервера WebApi.

Расписания и производственный календарь считаются по часовому поясу ОС сервера WebApi — проверьте его. Параметра Scheduler:TimeZoneId, как в патчах 1.26.7 LTS, в 1.26.9 нет.

Где это в меню

  • Задания → Все задания — право Assignments.View; запуск и остановка — Assignments.Run.
  • Задания → Расписания — Schedule.View.
  • Задания → Производственный календарь — только в режиме нескольких календарей (ProductionCalendar:Multiple). Иначе календарь — в Настройки → Система.

Создать задание

  1. Все задания → Добавить задание. Заполните Наименование и RPA-проект. Проект у сохранённого задания не меняется — для другого проекта создайте новое задание.
  2. Настройте запуск: Одновременно работающие роботы (от 2 до 5000) и Уникальный запуск, Разрешить наложение, Значения аргументов («Из версии проекта» или «Из задания»), Автоматически применять активную версию проекта.
  3. Раскройте Запуск по триггеру → Добавить триггер, выберите Тип триггера и заполните его поля.
  4. Сохранить, затем Запустить. Состояние задачи — «Выполняется»

Редактировать можно только остановленное задание. Посмотреть параметры без остановки — действие Просмотр.

Расписания и календарь

Cron-строка — формат Quartz, пример из формы: 0 0 12 * * ?. Оркестратор проверяет её при сохранении. В расписании можно отметить Согласовано с производственным календарем (24 x 5) или Суббота и воскресенье – рабочие дни (24 x 7). Отдельного «календарного» триггера нет: календарь привязывается к расписанию.

Состояния задания

Колонка показывает состояние задания, а не робота: «Новое», «Выполняется», «Выполнено», «На паузе», «Ошибка» (enum AssignmentStatus). Флаг Продолжить после ошибки решает, остановится ли задание после ошибки.

Массовые действия: Остановить все и Запустить все остановленные. Для них нужны отдельные права Assignments.StopAllRunning и Assignments.StartAllPaused.

UI4 предлагает тип «Запуск при изменении очереди обмена данными» (ExchangeQueue = 2), а в бэкенде он помечен «Не используется больше». Уточнить у разработки: убрать из списка или описать, что он делает.
