RPA-проекты

Применимо: 1.26.9UI4

Загрузка проектов, версии, активная версия и публикация из Студии.

Где это в меню

RPA-проекты: вкладки Все RPA-проекты, Запуски, Очередь проектов. Все три требуют права RpaProjects.View. Загрузка — RpaProjects.Create, изменение — RpaProjects.Edit, предрелизные версии — отдельная группа прав PreReleaseVersion.*.

Загрузить проект или версию

  1. Новый проект: Все RPA-проекты → Добавить RPA-проект. Новая версия существующего: Добавить версию в строке проекта.
  2. Выберите архив в поле Архив (zip). Оркестратор читает zip: процессы — файлы *.ltw, метаданные (имя, описание, версия, признак предрелиза, теги) — из первого *.ltp. Заполнились Главный процесс, Версия проекта, Предрелиз (RC)
  3. Если нужно, отметьте Сделать активной версией и нажмите Сохранить. Версия появилась в Связанные версии

Ошибка «Не верный уровень вложенности при упаковке архива» значит, что файлы проекта лежат в архиве не на том уровне. Пересоберите архив в Студии.

Как устроены версии

Поле в UI4Откуда берётся
Версия (внутренняя) (v0 … vN)Назначает Оркестратор: максимум среди неотключённых версий + 1. Первая — 0, либо 1 при RpaProject:NumerateProjectVersionsFromOne.
Версия проектаСтрока из файла .ltp, формат задают разработчики.
Предрелиз (RC)Из .ltp. Менять признак после загрузки можно, пока RpaProject:AllowOverridePreRelease = true (по умолчанию); иначе — ошибка 409.
Активная версияОдна на проект. Переключается действием Назначить активной версией.
Источник публикацииТеги orch, studio, git.

При смене активной версии задания и триггеры с флагом Автоматически применять активную версию проекта переходят на неё сами. Ограничения аргументов копируются из активной версии в новую.

Публикация из Студии

Студия публикует проект через те же методы API, что и форма загрузки. Если источник не передан, Оркестратор ставит studio, когда у пользователя есть роль Studio, иначе orch. Отдельного метода публикации из Git в API 1.26.9 нет — есть только значение источника git.

Параметры проекта

Кроме имени и описания в форме есть: Приоритет, Конфигурация запуска (Стандартная / Специальная), Версии дистрибутива робота, Ограничение числа запусков, Без повторов в очереди, Не очищать папку, Запуск с повышенными правами, Закрыть RDP-сессию, Освободить сессию принудительно, Задержка освобождения RDP-сессии (мсек). Аргументы и их ограничения — в разделе Аргументы.

Где хранятся архивы

ПараметрНазначениеПо умолчанию
RpaProjectArchiveUpload:StoreTypeХранилище архивов: LocalDb, S3, FileSystem (устарело)LocalDb

Ограничения размера в самом Оркестраторе нет. Ограничивает nginx: client_max_body_size 700m в блоке server.

Старая настройка RpaProjectArchiveUpload:DbStore с 1.26.9 не читается — используйте StoreType. Комментарий в коде говорит «с 1.26.8.0», но ветка 1.26.8.0 её ещё читает. Подробнее — Изменения в конфигах между LTS.

Автоочистки старых версий проектов в коде нет. Если в старых доках она описана — уточнить у разработки.
