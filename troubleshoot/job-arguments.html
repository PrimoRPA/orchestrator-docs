Задание запускается не с теми значениями аргументов

Применимо: 1.26.9WindowsLinuxDocker

Значения аргументов, заданные в задании, заменились значениями из версии проекта, пропали или не принимаются при запуске. На странице описано, когда Оркестратор перезаписывает аргументы задания и как проверяются ограничения аргументов.

Перед началомправа на просмотр и изменение заданий и RPA-проектов — Задания и триггеры
Результатзадание запускается с нужными значениями аргументов

Симптомы

  • После того как новая версия проекта назначена активной, значения аргументов в задании заменились значениями из этой версии. То же происходит при возврате к прежней версии — Значения задания заменились значениями версии.
  • После очистки старых версий проектов у заданий пропали значения аргументов — Аргументы пропали после очистки старых версий.
  • При сохранении аргументов или ручном запуске возвращается 400 «Аргумент …: значение должно быть одним из: …» — Значение не входит в список допустимых.

Вероятные причины

  • В задании выбран режим «Из версии проекта». Это значение по умолчанию для нового задания; правила пересчёта — в разделе Когда аргументы задания перезаписываются.
  • Удалены версии проекта, на аргументы которых ссылалось задание.
  • Значение не совпадает ни с одним из допустимых значений аргумента.

Когда аргументы задания перезаписываются

Аргументы задания пересчитываются только при назначении активной версии проекта (действие Назначить активной версией или Сделать активной версией при загрузке). Загрузка новой версии без назначения активной аргументы заданий не меняет.

Пересчитываются только задания с включённым флагом Автоматически применять активную версию проекта: задание переводится на новую активную версию, а аргументы заполняются по полю Значения аргументов.

Значения аргументовЧто происходит при смене активной версии
Из версии проектаВсе аргументы задания заменяются значениями аргументов новой активной версии — теми, что заданы у версии в разделе Аргументы. Значение по умолчанию для нового задания
Из заданияАргументы сопоставляются по имени. Для аргумента, который есть и в задании, и в новой версии, сохраняется значение задания. Новый аргумент получает значение из версии. Аргумент, которого нет в новой версии, удаляется из задания

У задания без флага Автоматически применять активную версию проекта версия проекта и аргументы при смене активной версии не меняются.

Что проверить

  1. Откройте задание и посмотрите поля Автоматически применять активную версию проекта и Значения аргументов. Известен режим пересчёта аргументов
  2. В событиях Оркестратора найдите «Проект назначен главной версией» (411) по нужному проекту. Время смены версии совпадает со временем изменения аргументов
  3. Откройте аргументы активной версии проекта (раздел Аргументы в строке версии) и сверьте их с аргументами задания. Значения в задании совпадают со значениями версии — аргументы взяты из версии
  4. При ошибке 400 откройте у аргумента Ограничения и сверьте значение со списком Допустимые значения. Нарушения ограничений записываются в журнал WebApi строкой «Значение аргумента RPA-проекта не соответствует ограничениям: …». Найдено ограничение, которое не выполняется

Как исправить

Значения задания заменились значениями версии

  1. Откройте задание на редактирование и выберите Значения аргументов = «Из задания». Подсказка поля: «Значения аргументов задания сохраняются при обновлении версии проекта.»
  2. Задайте нужные значения аргументов задания и сохраните. После следующего назначения активной версии значения в задании сохранились

Режим «Из версии проекта» подходит, если значения аргументов поддерживаются в самой версии: при загрузке версии они берутся из архива проекта, затем их можно изменить в разделе Аргументы версии до назначения её активной.

Если задание должно оставаться на конкретной версии, выключите Автоматически применять активную версию проекта. Задание перестанет переходить на новые активные версии.

Аргументы пропали после очистки старых версий

После удаления старых версий проекта у заданий могут пропасть значения аргументов. Откройте аргументы затронутых заданий и задайте значения заново. Для восстановления привязки аргументов в БД обратитесь в техническую поддержку.

Через UI4 версию, которая используется в задании, удалить нельзя: возвращается «Проект используется в задании.»

Значение не входит в список допустимых

Ограничения аргумента задаются в Оркестраторе, в файле проекта их нет: Аргументы версии → Изменить ограничения → Допустимые значения (одно значение на строку). Значение аргумента сравнивается со списком как строка целиком, с учётом регистра, после удаления пробелов по краям. Значение из нескольких элементов списка через запятую (например, 006,019) с отдельными элементами не совпадает и отклоняется.

  1. Укажите ровно одно значение из списка Допустимые значения, в том же регистре.
  2. Если проекту нужно передавать несколько значений, уберите список допустимых значений и задайте проверку полем Регулярное выражение. Аргументы сохраняются, запуск проходит без ошибки 400
