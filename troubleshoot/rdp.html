Сессия робота не поднимается или не видна в консоли

Применимо: 1.26.9WindowsLinux

Для Windows-машин сессии роботов поддерживает и отображает в браузере служба RDP2. Для Linux-машин консоль открывается напрямую на агенте. Сначала определите, какой из случаев применим.

Как исправить

Отказ во входе: «Неверные учетные данные»

  1. Если в карточке RDP-пользователя «Неверные учетные данные», задайте верный пароль. RDP2 после ошибки учётных данных перестаёт переподключаться к этому пользователю.
  2. Если пароль верен, а вход через mstsc проходит, найдите причину отказа в журнале «Безопасность» машины робота на время попытки (блокировка, срок действия учётной записи или пароля, права на вход по RDP), устраните её, затем в карточке RDP-пользователя выключите Неверные учетные данные и сохраните. «RDP-сессия активна» отмечено

RDP2 запрашивает у сервера проверку подлинности на уровне сети (NLA), TLS или стандартную защиту RDP, сервер выбирает сам. Отключать NLA на машинах роботов не требуется.

Служба RDP2 запущена, но новые сессии не поднимаются

  1. Снимите дамп процесса RDP2 и перезапустите службу. При остановке RDP2 закрывает все свои RDP-подключения. в журнале RDP2 на уровне Debug появляются «RdpClient {id} connected»
  2. Проверьте журналы служб удалённых рабочих столов на машине робота за время сбоя.

Сессию отключает сервер

Признак: в журнале RDP2 на уровне Debug — «RDP client {id} closed: …» с текстом «…replaced by another connection.» или «…initiated by an administrative tool on the server.». Найдите второе подключение под той же учётной записью: журналы TerminalServices на машине робота, второй экземпляр RDP2 с тем же набором машин, роботы разных машин с одной учётной записью.

Несколько служб RDP2

Укажите в RDP:RdpBaseUrls ключами адреса машин роботов, перечислите эти машины в AddressFilter соответствующей RDP2 и добавьте в nginx для каждой RDP2 отдельный location с upstream на её машину. Перезапустите WebApi и nginx. трансляция открывается для машин каждой RDP2

Консоль не открывается

Windows. Задайте RDP:RdpBaseUrl внешним адресом, который доступен из браузера (в поставке — через /rdpstream nginx), и перезапустите WebApi.

Linux. Откройте https://{IP машины}:5002 в браузере и примите сертификат. Если на машине робота нет /usr/bin/Xvnc, установите Xvnc.

UI4 1.26.9 для Linux-консоли всегда использует https и порт 5002, а не настройки порта и протокола агента. Если агент слушает другой порт или HTTP, консоль не откроется.

Отключённые сессии накапливаются

Включите завершение отключённых сессий: RDP:EnabledLogOffDisconnectedRDPUsers=true. Для Linux-машин операция не поддерживается. Если сессия не завершается и после этого, поднимите уровень журнала агента до Information и найдите ошибку разлогона «Failed LogOffDisconnectedRDPUsers - {error}». После исчерпания RDP:MaxAttemptStartLogOff или RDP:MaxAttemptLogOff попыток Оркестратор прекращает попытки, и сессия остаётся отключённой; завершите её вручную.

Известные ошибки версий

RDP2 1.26.7.1 не подключается к машинам на Windows Server 2025

В журнале RDP2 — «Error connecting RdpClient {id}: (FailedToConnect) RDP connection to {адрес}:3389 failed: The write operation failed, see inner exception.». Обновите RDP2 до последней сборки своей версии. Временный обход для Оркестратора 1.26.7 — служба RDP2 версии 1.26.3.

Linux, агент до 1.26.7.4: в теневой сессии робота не открывается проводник

Исправлено в агенте 1.26.7.4. Обновите агент.

Как это устроено

Windows. RDP2 с заданным интервалом запрашивает у WebApi список сессий (GET {Orchestrator:BaseUrl}/api/RdpSessions; если задан Mqtt:Url — через MQTT). Затем RDP2 подключается по RDP к пользователям, у которых включено Автоматически поддерживать RDP-сессию, и сообщает статус. Браузер получает адрес RDP2 из RDP:RdpBaseUrl WebApi и открывает WebSocket {RdpBaseUrl}/api/Desktop/ws/{id}/jpg. В поставке nginx проксирует /rdpstream/ на RDP2 (127.0.0.1:5102).

RDP2 обрабатывает список сессий циклами с интервалом RdpClientConnectionUpdateInterval. За один цикл открывается не больше MaxSessionsLimit новых подключений; остальные ждут следующих циклов. RDP-пользователи Linux-машин и пользователи с отметкой «Неверные учетные данные» в список для RDP2 не попадают. Изображение рабочего стола RDP2 формирует только пока сессию просматривают из консоли.

MQTT. Обмен WebApi и RDP2 через MQTT включается, только если в обеих службах задан Mqtt:Url; без него используется REST. Если Mqtt:Url не задан, WebApi при старте пишет предупреждение «MQTT bus client is invalid, REST is used», а при запуске робота, для которого поднимается RDP-сессия, — записи уровня Error «Failed connecting to MQTT: Value cannot be null. (Parameter 'uriString')» и «Failed publishing to RdpSession: …». Эти записи не означают сбоя: запуск продолжается, сессии поднимаются через REST.

События сессии. «RDP - DisabledKeepRDPSession» регистрируется, когда поддержка сессии снимается: вручную (флажок Автоматически поддерживать RDP-сессию), после завершения проекта с флажком После выполнения проекта роботом закрыть RDP-сессию или когда робот признан недоступным. «Робот не доступен - RDPLogOff» регистрируется в двух случаях: принудительная остановка робота, у проекта которого включено закрытие RDP-сессии, и освобождение лицензии робота по тайм-ауту (RobotStart:IntervalForReleaseInSeconds, по умолчанию 300 с), если не задано RobotStart:DisableReleaseRdpSessionTimeOut=true. После этих событий завершение сессии — штатное поведение.

Linux. RDP2 не участвует. Агент запускает для операции робота сервер Xvnc. UI4 открывает консоль запросом https://{IP машины}:5002/api/Desktop/… напрямую к агенту и только для текущей операции робота.
