Файлы дистрибутивов, проектов и пакетов: хранилище и публикация

Применимо: 1.26.9WindowsLinuxDocker

Дистрибутив робота отображается как отсутствующий в хранилище, хотя файл на месте; растёт каталог временных файлов WebApi; NuGet-пакет не публикуется из Оркестратора. Где WebApi хранит файлы и какими параметрами это задаётся, описано в Хранилища; здесь — причины неполадок и способы исправления.

Перед началомдоступ к журналу WebApi и к серверу или контейнеру WebApi — Журналы служб
Результатфайлы доступны всем узлам WebApi, пакеты публикуются в NuGet-сервер

Симптомы

  • После загрузки дистрибутива робота в колонке Наличие в хранилище через несколько секунд отображается «Нет», хотя файл дистрибутива есть в папке и доступен для чтения. Рядом может отображаться отметка «Долгое время от некоторых нод нет подтверждения» — «Наличие в хранилище» = «Нет».
  • На сервере или в контейнере WebApi растёт каталог временных файлов (в Docker-образах — /tmp) — Растёт каталог временных файлов.
  • Пакет не публикуется в NuGet-сервер из Оркестратора, хотя напрямую в NuGet-сервер загружается. В журнале WebApi повторяется «Ошибка обработки задания Publish для пакета … NuGet-сервера: …» — Пакет не публикуется в NuGet-сервер.

Вероятные причины

  • Несколько экземпляров WebApi работают с одной БД, а папки дистрибутивов у них разные. Каждый экземпляр проверяет файл в своей папке.
  • WebApi сохраняет файлы на локальный диск и не удаляет их. Это загруженные NuGet-пакеты и, при устаревшем способе хранения, архивы проектов.
  • WebApi не получает ответ от NuGet-сервера. Истекает таймаут запроса или соединение сбрасывается при установке TLS.

Что проверить

  1. Определите, сколько экземпляров WebApi подключено к БД: события «Добавился узел» (90500) и «Потерян узел» (90501), список процессов и подов. Известны все работающие узлы WebApi
  2. Найдите в событиях Оркестратора «Рассинхронизация дистрибутива робота на узлах» (1204) и событие 1205 («мерцание» подтверждения). Известно, есть ли рассогласование между узлами
  3. На каждом узле без S3 проверьте файл <RobotDistrUpload:TargetFilePath>/<PrefixFolder><Id>/LTools.Robot.x64.zip (или .x86.zip) и его размер. Файл есть на всех узлах, размер совпадает с размером загруженного дистрибутива
  4. Проверьте размер каталогов NuGet:UploadPackagePath и RpaProjectArchiveUpload:TargetFilePath (в Docker-образах /tmp/OrchNuGet и /tmp/RpaProjects) и значение RpaProjectArchiveUpload:StoreType. Известно, какой каталог растёт
  5. В Настройки → NuGet → Задачи посмотрите задачи публикации с ошибкой, в журнале WebApi — текст ошибки после «NuGet-сервера:». Известен текст ошибки публикации

Как исправить

«Наличие в хранилище» = «Нет» при нескольких экземплярах WebApi

Каждый узел WebApi раз в 3 секунды проверяет у себя каждый дистрибутив робота и записывает в БД своё подтверждение. Без S3 узел проверяет файл в папке RobotDistrUpload:TargetFilePath, с S3 — объект в бакете; подтверждение положительное, только если размер файла совпадает с загруженным. В колонке отображается «Да», только если все работающие узлы подтвердили наличие. Если узел не подтверждает дольше InstanceInfo:NodesDesynchronizationTimeout секунд (по умолчанию 60), записывается событие 1204. Остановленный узел исключается из проверки.

Дистрибутив сохраняется только на том узле, через который его загрузили. Если к той же БД подключён второй экземпляр WebApi со своей папкой, он файла не находит. Выполните тот шаг, который соответствует установке:

  1. Если второй экземпляр запущен ошибочно, остановите его. Через несколько секунд в колонке «Да»
  2. Если узлов должно быть несколько, подключите S3 (FileStore:Type=1) — см. Хранилища — либо скопируйте подпапку дистрибутива <PrefixFolder><Id> в папку дистрибутивов каждого узла. Нет события 1204, в колонке «Да»

У каждого узла должен быть свой InstanceInfo:Id — см. Масштабирование и отказоустойчивость. Дистрибутивы агента проверяются так же.

Растёт каталог временных файлов WebApi

Каталог (в Docker-образах)Что в нёмЧто делать
NuGet:UploadPackagePath (/tmp/OrchNuGet)NuGet-пакеты, загруженные через Опубликовать NuGet-пакет. После публикации файл не удаляетсяУдаляйте файлы пакетов, у которых нет незавершённых задач в Задачи по NuGet-пакетам
RpaProjectArchiveUpload:TargetFilePath (/tmp/RpaProjects)Архивы RPA-проектов, только при RpaProjectArchiveUpload:StoreType=0 (устаревший способ). Это основное хранилище архивов, а не временные файлыНе удаляйте файлы: без них версии проектов не скачиваются. Переведите хранение в БД или S3 (StoreType = 1 или 2) и разместите папку на постоянном томе

Встроенной очистки этих каталогов в WebApi нет. В Kubernetes содержимое /tmp пода, не вынесенное на том, удаляется при пересоздании пода.

При StoreType=0 в Docker и Kubernetes каталог архивов должен быть на постоянном томе. Иначе при пересоздании контейнера архивы проектов теряются.

Пакет не публикуется в NuGet-сервер

Публикация выполняется в фоне. Пакет сохраняется в NuGet:UploadPackagePath, в БД создаётся задача публикации. Раз в NuGet:TaskPeriod секунд (по умолчанию 2) WebApi берёт задачу и отправляет пакет запросом PUT {NuGetBaseUrl}/{PathBase}/api/v2/package. Задача с ошибкой повторяется через NuGet:RepeatErrorDelay минут (по умолчанию 2) без ограничения числа попыток, поэтому ошибки в журнале и в UI4 повторяются, пока задача не будет удалена или выполнена.

Параметр секции NuGetНазначениеПо умолчанию
NuGetBaseUrlАдрес NuGet-сервера—
PathBaseПуть, который добавляется к адресу. Пусто — не добавляетсяnuget
ApiKeyКлюч NuGet-сервера, зашифрован—
UploadPackagePathПапка для пакетов перед публикацией— (в Docker /tmp/OrchNuGet)
TaskPeriodПериод опроса задач, с2
RepeatErrorDelayЗадержка повтора задачи с ошибкой, мин2
TimeoutТаймаут запроса к NuGet-серверу, с10

Таймаут. Ошибка «The request was canceled due to the configured HttpClient.Timeout of 10 seconds elapsing.» означает, что NuGet-сервер не ответил за NuGet:Timeout секунд. Увеличьте таймаут и перезапустите WebApi:

"NuGet": {
  "Timeout": 60
}

Ошибка TLS. Ошибка «The SSL connection could not be established, see inner exception.» с внутренней «Connection reset by peer» означает, что соединение разорвано при установке TLS. Недоверенный издатель сертификата сам по себе к этой ошибке не приводит. Проверьте:

  1. Адрес, который собирается из NuGetBaseUrl и PathBase: протокол, порт и путь должны соответствовать NuGet-серверу.
  2. Доступность адреса с сервера или из контейнера WebApi, например запросом curl -v <NuGetBaseUrl>/<PathBase>/v3/index.json. Запрос из контейнера WebApi проходит без разрыва соединения

Прекратить повторы. Удалите задачу с ошибкой в Настройки → NuGet → Задачи (кнопка удаления в строке). Пакет можно опубликовать напрямую в NuGet-сервер.

Задачу публикации может взять любой узел WebApi, а файл пакета сохраняется на том узле, через который его загрузили. При нескольких узлах NuGet:UploadPackagePath должен указывать на общую для узлов папку.
