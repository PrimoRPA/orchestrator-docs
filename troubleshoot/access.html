Пользователь не видит папки, проекты или разделы

Применимо: 1.26.9WindowsLinuxDocker

Набор разделов и объектов, доступных пользователю, определяется правами его ролей и доступом к общим папкам. Права записываются в токен при входе, поэтому изменения роли начинают действовать только после повторного входа.

Что проверить

  1. Попросите пользователя выйти и войти снова. Раздел или объекты появились
  2. Откройте Роли пользователей и роль пользователя. Проверьте права в нужной категории и привязки в полях Группы AD или Роли KeyCloak. Право есть, группа или роль пользователя привязана
  3. Для AD в журнале WebApi найдите «Ошибка авторизации. Группа в AD … не имеет привязки к роли.» и строки «AD group SID: …» со списком групп пользователя. Для Keycloak — «Отсутствует привязка KeyCloak-ролей.» Группы из журнала совпадают с привязкой в роли
  4. Если включены общие папки, откройте Общие папки, нужную папку и Делегировать. Пользователь есть в списке с нужным уровнем доступа
  5. Если права на папки пропали у пользователей AD с заглавными буквами в логине, найдите привязки не в нижнем регистре запросом на чтение к БД Оркестратора: 
    SELECT "Id", "FolderId", "UserId", "AuthType"
FROM public."FolderUsers2"
WHERE "UserId" <> LOWER("UserId");
    Запрос не возвращает строк
  6. Чтобы узнать, в какой папке числится объект, выполните запрос на чтение (пример для робота): 
    SELECT "Id", "ObjectType", "FolderId", "RobotId", "RpaProjectId"
FROM public."FolderObjects2"
WHERE "RobotId" = <id робота>;
    Объект числится в ожидаемой папке

Как исправить

Права роли

Раздел меню в UI4 скрывается, если у пользователя нет ни одного права в его категории. Права считываются в UI4 при входе. При проверке на сервере права также берутся из токена. Срок действия токена — Security:Jwt:SessionLifetimeMin минут (в Dockerfile — 720). Привязки ролей Keycloak кэшируются в WebApi на 10 минут.

Права ролей Administrator и TenantAdministrator восстанавливаются по умолчанию при каждом запуске WebApi. Собственные ограничения задавайте в отдельной роли, а не в этих. Системные роли удалить нельзя: «Системная роль не может быть удалена.» Право управлять лицензиями есть только у Administrator.

Общие папки

Режим задаёт Folders:Mode: 0 — папки выключены (по умолчанию), 2 — общие папки. Доступ к папке выдаётся конкретному пользователю: локальному, AD или Keycloak. Уровни: «Только чтение», «Использование без редактирования», «Добавление, редактирование (без удаления объекта)», «Удаление». Выдать доступ может только владелец папки или администратор тенанта.

К корневой папке по умолчанию доступ есть у всех (Folders:RootFolderDefaultAccess=true). Если задать false, без явной выдачи прав пользователю возвращается «Нет прав на добавление объекта в корневую папку.»

Разрешения роли и доступ к папке не связаны: роль задаёт, какие действия доступны пользователю, папка — какие объекты он видит и с каким уровнем доступа. Нужны оба. Например, право редактирования в роли не позволяет изменять объекты папки, выданной с уровнем «Использование без редактирования».

Регистр логинов AD в привязках к папкам

Логин пользователя AD при входе приводится к нижнему регистру, а привязки к папкам (таблица FolderUsers2) сравниваются с ним точно. Новые привязки WebApi сохраняет в нижнем регистре. Привязки, созданные раньше с заглавными буквами, приводит к нижнему регистру миграция БД FolderUser2_Update4. Если запрос из шага 5 раздела Что проверить возвращает строки, убедитесь, что миграции БД выполнены, или выдайте права на папку заново через Делегировать.

Пользователь AD вне области поиска

Вход по SSO не ищет пользователя в AD: имя и группы приходят в билете Kerberos, поэтому StartPoint на вход не влияет. Окно делегирования папки (тип аутентификации AD) ищет пользователя запросом GET /api/Folders2/AdUser/{домен}?name=… в одной ветке: UsersStartPoint, а если он не задан — StartPoint. Пользователь вне этой ветки не находится, и форма показывает «Пользователь не найден». Указать несколько веток поиска нельзя.

Варианты:

  • Выдайте доступ через API. Метод PUT /api/Folders2/{id папки}/GrantFolderUsers не проверяет пользователя в AD. Требуется право на редактирование папок; выдать доступ может владелец папки или администратор тенанта. 
    { "Users": [ { "AuthType": 1, "AdUserId": "<логин>@<домен>", "AccessType": 1, "OperationType": 0 } ] }
    AuthType: 1 — AD; AccessType: 0 — только чтение, 1 — использование, 2 — добавление и редактирование, 3 — удаление; OperationType: 0 — добавить. Домен — ключ домена в ActiveDirectory:MultyForest.
  • Укажите в UsersStartPoint ветку, общую для нужных пользователей, например корень домена. Чем шире ветка, тем дольше поиск на большом домене.

Отличается ли ветка пользователя от точки поиска, проверьте по его DN в AD и по журналу WebApi уровня Debug: строка «Не удалось получить ничего по указанному фильтру […] для пользователя […] из AD.» Фильтр задаёт UserFilterTemplate, по умолчанию (&(objectCategory=user)(objectClass=user)(userPrincipalName={0})).

Перенос объектов между папками

Переносите в другую папку проект, а не робота. При переносе проекта вместе с ним переносятся все его версии, привязанные к нему роботы и связанные с этими роботами группы роботов, ассеты и очереди. При переносе отдельного робота связи с объектами исходной папки, в том числе привязка к проекту, разрываются. Из одной общей папки в другую объекты переносятся только в папку, владельцем которой является пользователь; иначе возвращается «Папка не найдена.»

Кнопки «Остановить все» и «Запустить все остановленные»

Кнопки на экране заданий показываются по правам роли: «Задания: Остановить все запущенные» и «Задания: Запустить все остановленные». Параметров конфигурации WebApi для скрытия этих кнопок нет: снимите права в роли.

Несколько узлов WebApi

Результаты фильтрации объектов по папкам кэшируются в памяти каждого узла WebApi на Folders:CacheDurationInSeconds (в классе 5 с). При изменении папки кэш сбрасывается только на узле, который обработал запрос; остальные узлы показывают прежние данные до истечения кэша. Перезапуск nginx не требуется.

Если после смены папки список заданий пуст или фильтр по проектам не применяется, сбросьте фильтр либо переключитесь в другую папку, вернитесь и дождитесь загрузки списка.

Предупреждения 403 от UI4 в журнале WebApi

UI4 отправляет ошибки своих запросов в журнал WebApi: «Ошибка клиента Error: {@ClientError}; Url: {ClientUrl}» с уровнем Warning и свойством ApplicationName = Primo.Orchestrator.UI. Request failed with status code 403 означает, что пользователь открыл раздел без прав (по закладке или прямой ссылке) и сервер отказал. Это штатное поведение. В записи есть ClientUrl (адрес раздела) и ClientUserId (пользователь): выдайте роли нужные права или уберите ссылку.

Тенант

Пользователь AD попадает в тенант первой подходящей роли по имени. Роли из других тенантов при этом отбрасываются. Если у пользователя роли в нескольких тенантах, проверьте, в какой он вошёл. Выбор тенанта при входе — Не получается войти: несколько тенантов.
