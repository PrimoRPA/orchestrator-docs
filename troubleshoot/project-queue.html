Проект висит в очереди и не уходит на робота

Применимо: 1.26.9WindowsLinuxDocker

Задания и ручные запуски ставят проект в очередь проектов. WebApi берёт проект из очереди и ищет подходящего робота. Если робота нет, проект ждёт и снова проверяется. Причину ожидания WebApi пишет в журнал.

Симптомы

  • На экране Очередь проектов проект стоит долго, хотя роботы свободны.
  • Роботы массово перестали брать проекты на одном или нескольких агентах.
  • В журнале WebApi: «… подходит для выполнения проекта …, но заблокирован Агентом.»

Каким должен быть робот

Проект уйдёт на робота, только если одновременно:

  • робот не отключён и развернут;
  • робот не выполняет проект (статус «Недоступен» — обычное состояние робота Оркестратора между запусками);
  • робот не заблокирован Оркестратором или агентом и не в процессе принудительной остановки;
  • платформа и версия дистрибутива подходят проекту;
  • машина прошла проверку связи, не превышено число одновременно работающих роботов на ней, у агента нет ошибки учётных данных;
  • робот в нужной папке (если включены папки);
  • Windows: сессия пользователя робота не завершается.

Что проверить

  1. Найдите в журнале WebApi строку по проекту. Известна причина ожидания
  2. Сверьте причину с таблицей ниже.
  3. Посмотрите список роботов: нет ли пометки «Заблокирован», какой Статус развертывания, Доступна ли машина. Есть хотя бы один робот, подходящий по всем условиям
Сообщение в журнале WebApiЧто делать
«… не запущен - отсутствуют свободные лицензии.»Все лицензии роботов заняты. См. Нет лицензии
«… не запущен - отсутствуют свободные роботы или достигнуто максимальное количество работающих роботов на машине.»Все подходящие роботы заняты, отключены или не подходят по условиям выше
«… машина робота (…) перегружена (CPU: …%, RAM: …%).»Машина дольше ProjectQueue:WorkerPerformanceHighDuration (60 с) в зоне высокой нагрузки, по умолчанию CPU выше 95 %. Разгрузите машину или задайте 0, чтобы не учитывать нагрузку
«Робот … подходит для выполнения проекта …, но заблокирован Агентом.»На агенте остался файл блокировки, см. ниже
«Проект с Id=… исключен из очереди ожидания - превышена максимальная длина очереди.»Очередь длиннее ProjectQueue:StaticProjectQueueLimiterMaxCount (1000). Уберите лишние запуски

Скриншот: экран «Очередь проектов» и значок блокировки робота в списке роботов, кнопка «Разблокировать».

Как исправить

Робот заблокирован агентом

На время запуска агент создаёт файл блокировки <каталог данных агента>/RobotLocks/<ключ робота> (имя каталога — Robot:LocksDir). Робот удаляет его сам при завершении. Если процесс робота упал или ещё не закрылся, блокировка остаётся. WebApi снимает её через RobotStart:TimeOutInMinutesForUnlock (в классе 5 мин, в Dockerfile 2 мин).

  1. Убедитесь, что процесс робота на машине завершён.
  2. Нажмите Разблокировать у робота. Если машина недоступна, придёт «Ошибка ручной разблокировки робота. Возможно, машина робота не доступна.» — восстановите связь с агентом. Пометки «Заблокирован» нет, проект ушёл из очереди

Проект нужно убрать из очереди

На экране Очередь проектов выберите проект и Удалить. Появится «Проект исключен из очереди выполнения».

Повторы в очереди

Флаг проекта Без повторов в очереди: если проект уже стоит в очереди, второй раз он не добавится. Флаг задаётся у RPA-проекта, а не у задания.

При публикации новой версии флаг берётся из публикации, а не из активной версии. Чтобы новая версия наследовала флаг активной, задайте в WebApi RpaProject:NoDuplicateDeferredQueueFromParentVersion=true (по умолчанию false) и перезапустите WebApi. После публикации новой версии флаг сохранился

Ограничение по нагрузке использует только CPU (ProjectQueue:WorkerPerformanceHighCPUOnly=true), хотя в сообщении выводится и RAM. Проверить на стенде.
