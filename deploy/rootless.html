Службы Linux без root

Применимо: 1.26.9Linux

В каждом Linux-архиве Оркестратора два юнита systemd: системный (от root) и пользовательский (без root). Целевая схема — пользовательские юниты. Здесь — чем они отличаются, что нужно для работы без root и как переключиться.

Два юнита: в чём разница

Оба юнита запускают один и тот же файл: WorkingDirectory=/opt/Primo/<Служба>, ExecStart=… --console, ASPNETCORE_ENVIRONMENT=ProdLinux, одинаковый SyslogIdentifier. Различается то, кто и как их запускает.

Что нужно для работы без root

  • Пользователь служб. Один для всех служб и nginx. В образах Docker он называется orch-user (UID 1001); на сервере имя выбираете сами.
  • Linger. sudo loginctl enable-linger <пользователь>. Без него службы стартуют только после входа пользователя и останавливаются после выхода. Проверка: loginctl show-user <пользователь> --property=Linger — Linger=yes.
  • Владелец каталогов. /opt/Primo/<Служба> и /opt/Primo/nginx принадлежат пользователю служб. В /opt/Primo/nginx юнит при каждом старте создаёт logs (журналы и nginx.pid) и temp — нужна запись.
  • Каталоги данных. Пользователю нужна запись во все каталоги из конфигов служб: у WebApi — RobotDistrUpload:TargetFilePath, AgentDistrUpload:TargetFilePath, RpaProjectArchiveUpload:TargetFilePath, NuGet:UploadPackagePath, LogsDump:Path, LogsDump:ArchPath, DPA:TmpProjectPath; у RobotLogs — ScreenFileUpload:ScreenFilePath; у NuGet2 — FileSystem:Path; у ArcSight — Files:Path; каталоги файловых журналов Serilog, если они заданы.
  • Файлы на чтение. Ключ сертификата nginx cert1.rsa — владелец пользователь служб, права 600. Keytab для входа через Kerberos (ActiveDirectory:MultyForest:<имя>:KerberosKeytabPath), если он хранится в файле.
  • Команды — под самим пользователем. Копируйте файлы и вызывайте systemctl --user в его сессии, не через sudo: иначе файлы получат владельца root и юнит не запустится.

Открыть сессию пользователя можно входом по SSH или из своей сессии:

sudo su - <пользователь>
export XDG_RUNTIME_DIR=/run/user/$(id -u)

Без XDG_RUNTIME_DIR команда systemctl --user после su не найдёт менеджер пользователя.

Порт ниже 1024 для nginx без root (например, 443): способы в коде не описаны, поставка предлагает для этого вариант от root. Уточнить, поддерживаются ли setcap или net.ipv4.ip_unprivileged_port_start.

MachineInfo вызывает lsblk --nodeps -no serial и cpuid. Проверить на стенде, что без root они отдают те же значения, что от root: иначе после перехода изменятся параметры машины для лицензии.

Агент

Агент в обоих вариантах работает от Agent:UserName (по умолчанию agent), разница только в том, кто его запускает: системный менеджер (User=agent) или менеджер самого agent. Работа агента без root поддержана с версии 1.24.1.

  • Обновление агента из Оркестратора (AgentUpdater) останавливает и запускает агент командой systemctl --user stop|start Primo.Orchestrator.Agent. Поэтому основной вариант — пользовательский юнит под этим именем.
  • Для пользователя агента нужен linger, как и для служб.
  • Права через sudo без пароля агенту нужны в обоих вариантах: /usr/bin/systemd-run … /opt/Primo/Agent/launch-as-user.expect (запуск роботов) и /usr/sbin/reboot (перезагрузка машины из Оркестратора).
  • В обоих юнитах агента задано UMask=0002; в пользовательском нет Restart=always.

Как переключиться с root на пользовательские юниты

  1. Остановите и удалите системные юниты (повторите для каждой службы и для Primo.Orchestrator.Nginx): 
    sudo systemctl disable --now Primo.Orchestrator.WebApi
sudo rm /etc/systemd/system/Primo.Orchestrator.WebApi.service
sudo systemctl daemon-reload
    systemctl list-units 'Primo.Orchestrator.*' ничего не показывает
  2. Создайте пользователя служб (если его нет) и включите linger: 
    sudo useradd -m -s /bin/bash orch-user
sudo loginctl enable-linger orch-user
  3. Отдайте пользователю каталоги служб, nginx (включая созданные от root logs и temp) и каталоги данных: 
    sudo chown -R orch-user:orch-user /opt/Primo
sudo chown -R orch-user:orch-user <каталоги данных из конфигов>
    find /opt/Primo ! -user orch-user ничего не выводит
  4. Под orch-user установите пользовательские юниты и запустите службы в обычном порядке (MachineInfo, WebApi, остальные, nginx): 
    mkdir -p ~/.config/systemd/user
cp /opt/Primo/WebApi/Primo.Orchestrator.WebApi.user.service ~/.config/systemd/user/Primo.Orchestrator.WebApi.service
systemctl --user daemon-reload
systemctl --user enable --now Primo.Orchestrator.WebApi
    Юнит NuGet2 — /opt/Primo/NuGet2/Primo.Orchestrator.NuGet.user.service, nginx — Primo.Orchestrator.Nginx.user.service из поставки. systemctl --user list-units 'Primo.Orchestrator.*' — все active running; ps -eo user,cmd | grep Primo.Orchestrator показывает orch-user
  5. Перезагрузите сервер. службы поднялись без входа orch-user в систему

Агент переключается так же: остановите и удалите /etc/systemd/system/Primo.Orchestrator.Agent.service, включите linger для agent и под ним установите Primo.Orchestrator.Agent.user.service в ~/.config/systemd/user/.

Обратно на root — наоборот: systemctl --user disable --now под пользователем, файлы *.service (без .user) — в /etc/systemd/system/, затем sudo systemctl enable --now. У nginx от root каталог www должен быть доступен всем на чтение.

Проверить на стенде переход с root: не мешают ли службам файлы, оставшиеся от процессов root (например, файлы именованных мьютексов .NET — WebApi и другие службы при старте берут глобальный мьютекс Global\{Primo.Orchestrator.<служба>…}).

Старые доки: «на Linux службы устанавливаются и работают от root». В 1.26.9 в архивах всех служб, NuGet2, nginx и агента есть пользовательские юниты, в поставке nginx — отдельная инструкция без root (readme-nginx.linux.md).
