Как проверить, что всё работает

Применимо: 1.26.9WindowsLinuxDocker

Проверка после установки или обновления: состояние каждой службы, связь с агентами и работа через UI4.

Эндпоинты проверки состояния

Каждая служба (WebApi, MachineInfo, RobotLogs, Analytic, Notifications, States, Queues, Licenses, LogEventsWebhook, NuGet2, RDP2, ArcSight, агент) отвечает на три адреса без авторизации:

АдресЧто значит
/healthОбщее состояние (у большинства служб совпадает с readiness)
/health/readinessГотова принимать запросы
/health/livenessПроцесс жив

Ответ — Healthy (HTTP 200) или Unhealthy (HTTP 503).

Когда readiness будет Unhealthy

СлужбаУсловие готовности
WebApi, MachineInfo, Notifications, LogEventsWebhook, ArcSightВсегда Healthy, если процесс отвечает. Подключение к БД и RabbitMQ эта проверка не показывает.
RobotLogs, Analytic, States, Queues, Licenses, RDP2Healthy, когда служба знает адрес WebApi: задан Orchestrator:BaseUrl или адрес пришёл от WebApi.
АгентHealthy только после того, как WebApi хотя бы раз к нему обратился (т. е. машина зарегистрирована и опрошена).
MCP Server/mcp/health; 503, пока Оркестратор недоступен.

Как проверить

На сервере (порты — со страницы Порты и сетевой трафик):

curl -f http://localhost:5001/health        # WebApi
curl -f http://localhost:5051/health        # MachineInfo
curl -f http://localhost:56748/health       # RobotLogs
curl -k -f https://localhost:44392/api/Version   # WebApi через nginx, без авторизации

С сервера WebApi — до агента:

curl -k https://<IP машины робота>:5002/api/Worker   # 200 и версия агента
curl -k https://<IP машины робота>:5002/api/Version

Docker

  1. Выполните docker compose ps. у всех сервисов статус healthy; compose сам опрашивает /health каждые 30 секунд
  2. Если сервис unhealthy — docker compose logs <сервис>. Службы пишут журнал в консоль в формате JSON.

Linux

  1. systemctl status Primo.Orchestrator.<Имя> (или systemctl --user status …). active (running)
  2. Журнал службы: journalctl -t Primo.Orchestrator.<Имя> — имя задано в юните (SyslogIdentifier).
  3. nginx: /opt/Primo/nginx/logs/nginx_error.log.

Windows

  1. Get-Service Primo.Orchestrator.*. все службы Running
  2. Если служба не стартует — запустите её .exe с аргументом --console из каталога службы и посмотрите ошибку в консоли.

В UI4

  1. Настройки → Лицензии. есть действующая лицензия
  2. Настройки → Система → Машины роботов. у каждой машины заполнены Доступна и Версия агента
  3. Тестовый запуск робота — см. Первый запуск. событие запуска в Журналы → События оркестратора

Старые доки: проверка агента https://{IP}:5002/api/Worker «вернёт HTTP 204». По коду 1.26.9 GET api/Worker возвращает 200 и строку версии агента.

Healthcheck WebApi не проверяет БД и RabbitMQ — для мониторинга этого мало. Описать в «Мониторинг и метрики» метрики Prometheus (порт 10052) как основной сигнал.

В Docker (ubuntu) у nginx нет отдельного location /health: https://localhost:44392/health отдаёт index.html с кодом 200. Проверяет только nginx, не службы.
