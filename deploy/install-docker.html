Установка в Docker

Применимо: 1.26.9Docker

Страница проведёт от чистого Linux-сервера до страницы входа в Оркестратор. Всё ставится на один сервер одним compose-файлом: PostgreSQL, RabbitMQ, службы Оркестратора и веб-интерфейс.

Перед началомLinux-сервер, доступ по SSH с правами sudo, файлы из Дистрибутивов, логин и пароль от реестра образов Primo RPA
Результатвсе контейнеры в состоянии healthy, по адресу https://<адрес сервера>:44392 открывается страница входа

Стенд или промышленная установка

Шаги одинаковые, разница — в том, что можно оставить как в поставке.

Сертификат HTTPSсамоподписанный, создаётся одной командой на шаге 4выпущен вашим удостоверяющим центром на имя сервера
Пароли и ключи в compose-файлеможно оставить из поставкизаменить все до первого запуска — шаг 5
Порты PostgreSQL и консоли RabbitMQможно оставить открытымизакрыть — шаг 5

Стенд нельзя превратить в промышленную установку сменой паролей на ходу: лицензия привязывается к ключу из compose-файла, а пароли в базе шифруются при первом запуске. Для промышленной установки пройдите шаг 5 до запуска.

В Docker Оркестратор работает только с PostgreSQL. Нужен MS SQL Server — выбирайте Установку служб на Windows Server.

Шаги

Команды выполняйте на сервере. В примерах сервер — Ubuntu 24.04, рабочий каталог — /opt/Docker.

  1. Установите Docker. Если Docker уже стоит, переходите к проверке в конце шага. 
    sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}") stable" | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
    Для другой ОС возьмите команды из официальной инструкции Docker. команда sudo docker compose version печатает номер версии
  2. Создайте каталог и положите в него файлы. 
    sudo mkdir -p /opt/Docker
cd /opt/Docker
    Скопируйте в каталог два файла из поставки и назовите их так:
    Файл в поставкеИмя в каталоге
    orchestrator/docker/docker-compose-ubuntu.ymldocker-compose.yml
    orchestrator/data/NGINX/nginx.docker.confnginx.conf
    команда ls /opt/Docker показывает docker-compose.yml и nginx.conf
  3. Укажите адрес сервера. Это адрес, по которому Оркестратор будут открывать пользователи и роботы: DNS-имя или IP. IP сервера показывает команда hostname -I. Откройте файл: sudo nano docker-compose.yml. Адрес из примера, 10.0.0.18, стоит в двух строках — замените его в обеих: 
    base-url: &base-url https://10.0.0.18:44392
RDP__RdpBaseUrl: https://10.0.0.18:44392/rdpstream
    Порт 44392 и остальное в строках не трогайте. Если сервер работает не по московскому времени, в начале файла замените tz (например, Asia/Yekaterinburg) и TimeOffset (разница с UTC в часах, например 5). Строку culture не меняйте. команда grep -c "10.0.0.18" docker-compose.yml печатает 0
  4. Положите сертификат. В каталоге должны лежать сертификат cert1.crt и закрытый ключ cert1.rsa — именно с такими именами.

    Стенд. Создайте самоподписанный сертификат, подставив адрес сервера:

    sudo openssl req -x509 -newkey rsa:2048 -nodes -days 365 -keyout cert1.rsa -out cert1.crt -subj "/CN=<адрес сервера>"

    Промышленная установка. Сертификат на имя сервера выпускает ваша служба безопасности или удостоверяющий центр. Скопируйте файлы в каталог под именами cert1.crt и cert1.rsa; ключ должен быть без пароля.

    Веб-интерфейс в контейнере работает не от root, поэтому дайте ему право читать оба файла:

    sudo chown 101 cert1.crt cert1.rsa
    команда ls -l /opt/Docker показывает четыре файла, у обоих файлов сертификата владелец 101
  5. Только для промышленной установки: замените пароли и ключи. На стенде шаг пропустите.

    Все пароли и ключи собраны в начале compose-файла в блоке x-secrets:

    • Придумайте свои значения для всех строк с паролями и ключами.
    • У части паролей две строки: открытая и с окончанием -encrypted. Во вторую вписывается тот же пароль в зашифрованном виде. Зашифровать его можно утилитой PasswordEncryptor из поставки: запустите её, введите пароль, нажмите Enter и скопируйте строку, напечатанную после слов «Copy following string».
    • Пароли MCP Server (mcp-orch-pass, mcp-api-key) задаются одной строкой, без пары -encrypted.
    • primo-machine-key — ключ, к которому привязывается лицензия. Задайте свой до запроса лицензии и сохраните в надёжном месте: без него лицензию на новом сервере не восстановить.
    • Чтобы к PostgreSQL и консоли RabbitMQ нельзя было подключиться снаружи, удалите у служб 0postgres-db и 0rabbitmq строки ports: вместе со следующей за ними строкой с номером порта.
    в блоке x-secrets не осталось значений из поставки: команда grep -c "Qwe123" docker-compose.yml печатает 0
  6. Только если роботам нужны RDP-сессии: укажите адрес RDP2. Служба RDP2 в compose-файл не входит, её ставят отдельно — см. Установку служб. В nginx.conf найдите блок upstream rdpstream и замените в нём адрес на адрес машины с RDP2, порт 5102 оставьте. Если RDP2 нет или вы пока не знаете, нужна ли она, ничего не меняйте: адрес из примера запуску не мешает, его можно поправить позже.
  7. Войдите в реестр образов и запустите. Логин и пароль от реестра выдаёт Primo RPA. 
    sudo docker login nexus.primo-rpa.ru:8000
sudo docker compose up -d
    При первом запуске Docker скачивает образы, а служба web-api создаёт базу данных — это занимает несколько минут. Состояние смотрите командой: 
    sudo docker compose ps
    у всех служб в колонке STATUS стоит healthy

    Если через десять минут какая-то служба остаётся unhealthy или перезапускается, посмотрите её журнал: sudo docker compose logs <имя службы>. Имя службы — из колонки SERVICE.

  8. Откройте Оркестратор в браузере: https://<адрес сервера>:44392. С самоподписанным сертификатом браузер предупредит о небезопасном соединении — на стенде это ожидаемо, выберите «Дополнительно» и продолжите. открылась страница входа

Сервер без доступа в интернет

Как перенести образы на сервер в закрытом контуре

Образы скачивают на компьютере с интернетом и Docker, переносят файлом и загружают на сервере. Docker на сервере ставят из пакетов вашей ОС или внутреннего репозитория.

  1. На компьютере с интернетом положите docker-compose.yml в пустой каталог, войдите в реестр и скачайте образы: 
    docker login nexus.primo-rpa.ru:8000
docker compose pull
docker save -o images.tar $(docker compose config --images)
  2. Перенесите images.tar на сервер в /opt/Docker.
  3. На сервере загрузите образы и продолжайте с шага 2. Вход в реестр на шаге 7 не нужен. 
    sudo docker load -i /opt/Docker/images.tar

Пользователям и роботам нужен только порт 44392: все обращения идут через nginx.

Данные лежат в томах Docker и переживают пересоздание контейнеров: pgdata (база данных), rabbitmqdata, webapidata (загруженные дистрибутивы робота и агента), nugetdata. Отдельное файловое хранилище не нужно.

Порядок запуска задан в файле: web-api ждёт PostgreSQL, RabbitMQ и machine-info, остальные службы ждут web-api.
