Установка в Docker

Применимо: 1.26.9Docker

На странице описана установка Оркестратора на Linux-сервер без предустановленного ПО до открытия страницы входа. Все компоненты — PostgreSQL, RabbitMQ, службы Оркестратора и веб-интерфейс — устанавливаются на один сервер одним compose-файлом.

Перед началомLinux-сервер, доступ по SSH с правами sudo, доступ с сервера в интернет (без интернета — см. ниже)
Результатвсе контейнеры в состоянии healthy, по адресу https://<адрес сервера>:44392 открывается страница входа

Стенд или промышленная установка

Порядок установки одинаков. Различаются параметры, которые допускается оставить без изменений.

ЧтоОзнакомительный стендПромышленная установка
Сертификат HTTPSсамоподписанный, создаётся одной командой на шаге 4выпущен удостоверяющим центром организации на имя сервера
Пароли и ключи в compose-файледопускаются значения из поставкизаменить все до первого запуска — шаг 5
Порты PostgreSQL и консоли RabbitMQдопускается оставить открытымизакрыть — шаг 5

Для стенда достаточно сервера с 4 ядрами, 8 ГБ памяти и 40 ГБ диска: после запуска Оркестратор занимает около 2,5 ГБ памяти и 17 ГБ диска, из них 15 ГБ — образы.

Перевод стенда в промышленную эксплуатацию заменой паролей после запуска не предусмотрен: лицензия привязывается к ключу из compose-файла, а пароли в базе шифруются при первом запуске. Для промышленной установки шаг 5 выполняется до первого запуска.

В Docker Оркестратор работает только с PostgreSQL. Для работы с MS SQL Server используйте Установку служб на Windows Server.

Шаги

Команды выполняются на сервере. В примерах сервер — Ubuntu 24.04, рабочий каталог — /opt/Docker.

  1. Установите Docker. Если Docker уже установлен, перейдите к проверке в конце шага. 
    sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}") stable" | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
    Для другой ОС используйте команды из официальной инструкции Docker. команда sudo docker compose version печатает номер версии
  2. Создайте каталог и разместите в нём файлы. 
    sudo mkdir -p /opt/Docker
cd /opt/Docker
    Скачайте два файла из папки нужной версии и сохраните под указанными именами:
    Файл в поставкеИмя в каталоге
    orchestrator/docker/docker-compose-ubuntu.ymldocker-compose.yml
    orchestrator/data/NGINX/nginx.docker.confnginx.conf
    Файлы можно скачать непосредственно на сервер. Подставьте номер версии; для LTS-версии вместо raw-hosted-release указывается raw-hosted-lts: 
    V=<версия>
sudo curl -fsSL -o docker-compose.yml https://nexus.primo-rpa.ru/repository/raw-hosted-release/$V/orchestrator/docker/docker-compose-ubuntu.yml
sudo curl -fsSL -o nginx.conf https://nexus.primo-rpa.ru/repository/raw-hosted-release/$V/orchestrator/data/NGINX/nginx.docker.conf
    команда ls /opt/Docker показывает docker-compose.yml и nginx.conf
  3. Укажите адрес сервера. Это адрес, по которому к Оркестратору обращаются пользователи и роботы: DNS-имя или IP. IP сервера выводит команда hostname -I; если адресов несколько, используйте тот, по которому сервер доступен из сети пользователей. Откройте файл: sudo nano docker-compose.yml. Адрес из примера, 10.0.0.18, указан в двух строках — замените его в обеих: 
    base-url: &base-url https://10.0.0.18:44392
RDP__RdpBaseUrl: https://10.0.0.18:44392/rdpstream
    Порт 44392 и остальную часть строк не изменяйте. Если сервер работает не по московскому времени, в начале файла замените tz (например, Asia/Yekaterinburg) и TimeOffset (разница с UTC в часах, например 5). Строку culture не меняйте. команда grep -c "10.0.0.18" docker-compose.yml печатает 0
  4. Разместите сертификат. В каталоге должны находиться сертификат cert1.crt и закрытый ключ cert1.rsa; имена файлов менять нельзя.

    Стенд. Создайте самоподписанный сертификат, подставив адрес сервера:

    sudo openssl req -x509 -newkey rsa:2048 -nodes -days 365 -keyout cert1.rsa -out cert1.crt -subj "/CN=<адрес сервера>" -addext "subjectAltName=DNS:<имя сервера>,IP:<IP сервера>"

    В subjectAltName укажите имеющиеся значения: только DNS:…, только IP:… или оба. Без этого поля браузеры не принимают сертификат, в том числе добавленный в доверенные.

    Промышленная установка. Сертификат на имя сервера выпускает удостоверяющий центр или служба безопасности организации. Скопируйте файлы в каталог под именами cert1.crt и cert1.rsa; ключ должен быть без пароля.

    Веб-интерфейс в контейнере работает не от root, поэтому ему необходимо право чтения обоих файлов:

    sudo chown 101 cert1.crt cert1.rsa
    команда ls -ln /opt/Docker показывает четыре файла, у обоих файлов сертификата владелец — 101
  5. Только для промышленной установки: замените пароли и ключи. На стенде шаг не выполняется.

    Пароли и ключи заданы в начале compose-файла в блоке x-secrets:

    • Задайте собственные значения во всех строках с паролями и ключами.
    • Часть паролей задаётся двумя строками: открытой и с окончанием -encrypted. Во второй указывается тот же пароль в зашифрованном виде. Для шифрования используется утилита PasswordEncryptor: она находится в папке версии рядом со службами, архив primo-rpa-orchestrator-passwordencryptor-<версия>-linux.zip или …-windows.zip. На Linux после распаковки выполните chmod +x Primo.Orchestrator.PasswordEncryptor. Запустите утилиту, введите пароль и нажмите Enter; приглашение к вводу до этого не выводится. Скопируйте строку, напечатанную после слов «Copy following string». Утилита выводит введённый пароль на экран.
    • Пароли MCP Server (mcp-orch-pass, mcp-api-key) задаются одной строкой, без пары -encrypted.
    • primo-machine-key — ключ, к которому привязывается лицензия. Задайте собственное значение до запроса лицензии и сохраните его: без ключа восстановить лицензию на новом сервере невозможно. После выдачи лицензии ключ не меняйте: лицензии сразу становятся недействительными.
    • Чтобы задать собственные соль шифрования паролей и ключ подписи токенов, добавьте в x-secrets две строки, например primo-salt: &primo-salt <значение> и primo-signing-key: &primo-signing-key <значение>, а в раздел environment каждой службы Оркестратора — строки PRIMOSALT: *primo-salt и PRIMOSIGNINGKEY: *primo-signing-key. Пароли после этого шифруйте с той же солью: PasswordEncryptor принимает её вторым значением через пробел после пароля. Соль задавайте до запроса лицензии: после смены соли выданные лицензии становятся недействительными. Ключ подписи на лицензии не влияет.
    • Чтобы исключить подключение к PostgreSQL и консоли RabbitMQ извне, удалите у служб 0postgres-db и 0rabbitmq строки ports: вместе со следующей за ними строкой с номером порта.
    в блоке x-secrets нет значений из поставки (сверяется с исходным файлом построчно)
  6. Только если роботам нужны RDP-сессии: укажите адрес RDP2. Служба RDP2 не входит в compose-файл и устанавливается отдельно как служба — см. Установку служб. Рекомендуется отдельная машина; при небольшом числе RDP-сессий допускается установка на этот же сервер. В nginx.conf найдите блок upstream rdpstream и замените в нём адрес на адрес машины с RDP2, порт 5102 оставьте. Если RDP2 не используется или решение о ней не принято, оставьте файл без изменений: адрес из примера не препятствует запуску и может быть изменён позднее.
  7. Запустите. 
    sudo docker compose up -d
    При первом запуске Docker скачивает образы: службы Оркестратора — из реестра Primo RPA nexus.primo-rpa.ru:8000, PostgreSQL и RabbitMQ — с Docker Hub. Затем служба web-api создаёт базу данных. Запуск после скачивания занимает около трёх минут. Состояние служб выводит команда: 
    sudo docker compose ps
    у всех служб в колонке STATUS указано healthy

    Ответ not found или unauthorized по образам Оркестратора означает, что образы этой версии недоступны в реестре без входа. Войдите командой sudo docker login nexus.primo-rpa.ru:8000 с учётными данными, полученными от Primo RPA, и повторите запуск; при отсутствии учётных данных обратитесь в поддержку Primo RPA.

    Если через десять минут служба остаётся в состоянии unhealthy или перезапускается, проверьте её журнал: sudo docker compose logs <имя службы>. Имя службы — из колонки SERVICE. Журнал приложите к обращению в поддержку.

  8. Откройте Оркестратор в браузере: https://<адрес сервера>:44392. При самоподписанном сертификате браузер выводит предупреждение о небезопасном соединении; на стенде это ожидаемое поведение: выберите «Дополнительно» и продолжите. Чтобы исключить предупреждение, добавьте cert1.crt в доверенные корневые сертификаты на рабочих местах. открылась страница входа

Сервер без доступа в интернет

Как перенести образы на сервер в закрытом контуре

Образы скачиваются на компьютере с доступом в интернет и установленным Docker, переносятся файлом и загружаются на сервере. Docker на сервере устанавливается из пакетов ОС или внутреннего репозитория.

  1. На компьютере с доступом в интернет разместите docker-compose.yml в пустом каталоге и скачайте образы: 
    docker compose pull
docker save -o images.tar $(docker compose config --images)
  2. Перенесите images.tar на сервер в /opt/Docker.
  3. На сервере загрузите образы и продолжите с шага 2: на шаге 7 Docker использует загруженные образы. 
    sudo docker load -i /opt/Docker/images.tar

Данные хранятся в томах Docker и сохраняются при пересоздании контейнеров: pgdata (база данных), rabbitmqdata, webapidata (загруженные дистрибутивы робота и агента), nugetdata. Отдельное файловое хранилище не требуется.

Порядок запуска задан в файле: web-api ждёт PostgreSQL, RabbitMQ и machine-info, остальные службы ждут web-api.
