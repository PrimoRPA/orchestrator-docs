Установка в Docker

Применимо: 1.26.9Docker

Самый быстрый путь: весь Оркестратор поднимается одним файлом docker-compose.yml — PostgreSQL, RabbitMQ, все службы и UI на nginx с HTTPS.

Комусистемному администратору
Перед началомЧто подготовить — блоки «Дистрибутивы» и «Сертификаты»
Результатвсе контейнеры в статусе healthy, UI открывается по https://<адрес>:44392

Docker-поставка работает только с PostgreSQL. RDP2 в compose нет: если нужны RDP-сессии Windows-роботов, поставьте RDP2 отдельно, службой. Нужен MS SQL Server — выбирайте Установку служб.

Что нужно

  • Linux-сервер с Docker Engine и плагином docker compose.
  • Доступ к реестру образов Primo RPA.
  • В одном каталоге: docker-compose.yml, nginx.conf (это nginx.docker.conf из поставки), cert1.crt, cert1.rsa.

Шаги

  1. Заполните блок x-globals:
    • tz и TimeOffset — часовой пояс и смещение в часах;
    • culture — язык;
    • base-url — внешний адрес Оркестратора, например https://orch.example.local:44392. Он уходит в NuGet__NuGetBaseUrl, RobotDeployment__OrchBaseUrl, RobotDeployment__RobotLogsBaseUrl.
    в файле не осталось адреса из примера
  2. В сервисе web-api поправьте RDP__RdpBaseUrl: https://<внешний адрес>:44392/rdpstream. адрес совпадает с base-url плюс /rdpstream
  3. Замените все значения в x-secrets. Пароли с суффиксом -encrypted зашифруйте утилитой PasswordEncryptor; открытые и зашифрованные значения должны соответствовать друг другу. в файле нет паролей из примера
  4. primo-machine-key (CustomerBinding__Key у machine-info) — ключ, к которому привязывается лицензия вместо параметров оборудования. Задайте его до запроса лицензии.
  5. В nginx.conf в блоке upstream rdpstream укажите адрес машины с RDP2 (RDP2 работает вне compose). server <адрес RDP2>:5102;
  6. Положите cert1.crt и cert1.rsa рядом с compose. Другие имена — только если поправите пути в nginx.conf. файлы на месте, ключ читается
  7. Войдите в реестр (docker login) и запустите: 
    docker compose up -d
    docker compose ps показывает все сервисы в состоянии healthy
  8. Откройте https://<внешний адрес>:44392. открывается страница входа UI4

Порядок старта задан в compose: web-api ждёт здоровых PostgreSQL, RabbitMQ и machine-info, остальные службы — здоровый web-api. Первый старт web-api дольше обычного: он создаёт и мигрирует БД.

Порты 5432 и 15672 опубликованы на хосте. Если доступ к БД и консоли RabbitMQ извне не нужен — уберите их из ports.

Адрес клиентского реестра в коде указан только в комментарии скрипта сборки (azure/docker.ps1, путь primo-rpa/orchestrator, теги вида <версия>-<дата>-ubuntu). Уточнить адрес, способ получения учётных данных и офлайн-вариант (перенос образов через docker save/load).

Healthcheck сервиса ui обращается к https://localhost:44392/health, но в nginx.docker.conf отдельного location /health нет — запрос обслуживает location / (отдаёт index.html). Работает, но проверяет только nginx. В astra-шаблоне /health есть.

Образы на базе Astra Linux (docker/astra/) в 1.26.9 конвейером не собираются; их compose старее (порт 5080 по HTTP, без Queues/Licenses/MCP). Не описывать, пока не подтвердят поставку. Helm-чарты в k8s/helm — для внутреннего стенда.

Можно ли менять CustomerBinding__Key после выдачи лицензии — в коде не видно; уточнить у разработки.
