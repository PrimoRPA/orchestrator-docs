Машины роботов и агент

Применимо: 1.26.9WindowsLinux

На каждой машине роботов устанавливается агент Оркестратора: через него WebApi разворачивает и запускает роботов. После установки агента машина регистрируется в интерфейсе Оркестратора.

Как агент связан с Оркестратором

  • Агент слушает 5002 по HTTPS; к нему обращается WebApi (Tenants:Agent:Port, Tenants:Agent:Https).
  • Адрес Оркестратора агент получает из заголовка orchestrator-url в запросах WebApi (значение RobotDeployment:OrchBaseUrl). Задавать Orchestrator:BaseUrl в конфиге агента не обязательно.
  • Пока WebApi ни разу не обратился к агенту, /health/readiness агента отвечает Unhealthy — до регистрации машины это штатное состояние.

Установка агента

Вкладка выбирается автоматически по ОС, определённой браузером. Для установки агента на машину с другой ОС переключите вкладку.

Требуется: архив primo-rpa-orchestrator-agent-<версия>-windows.zip, PowerShell от имени администратора.

  1. Откройте порт агента: 
    New-NetFirewallRule -Name "Primo Agent (5002)" -DisplayName "Primo Agent (5002)" -Profile "Private, Domain, Public" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 5002
    правило Primo Agent (5002) есть в брандмауэре
  2. Задайте окружение: 
    [System.Environment]::SetEnvironmentVariable("ASPNETCORE_ENVIRONMENT", "ProdWin", [System.EnvironmentVariableTarget]::Machine)
  3. Распакуйте архив в C:\Primo\Agent: 
    Expand-Archive primo-rpa-orchestrator-agent-<версия>-windows.zip -DestinationPath C:\Primo\Agent
    При необходимости измените appsettings.ProdWin.json. Каталог роботов по умолчанию — C:\LTools (DeployRobot:RobotsPath).
  4. Зарегистрируйте и запустите службу: 
    New-Service -Name "Primo.Orchestrator.Agent" -BinaryPathName "C:\Primo\Agent\Primo.Orchestrator.Agent.exe" -DisplayName "Primo.Orchestrator.Agent" -StartupType Automatic
Start-Service "Primo.Orchestrator.Agent"
    Get-Service Primo.Orchestrator.Agent — Running; https://localhost:5002/api/Version возвращает версию агента

Роботов агент запускает заданиями Планировщика заданий Windows от имени пользователя робота.

Требуется: архив primo-rpa-orchestrator-agent-<версия>-linux.zip (в нём агент, LTools.Orchestrator.Agent.Runner, appsettings.Runner.json, launch-as-user.expect и юниты), права root.

  1. Создайте группу и пользователя агента (имена по умолчанию; другие имена указываются в Agent:GroupName и Agent:UserName): 
    sudo groupadd primo-rpa
sudo useradd -g primo-rpa -m -s /bin/bash agent
    id agent показывает группу primo-rpa
  2. Установите пакеты, которые использует агент при запуске роботов: expect, unzip, виртуальный экран Xvfb и утилиты xauth, xprop, dbus-launch. На Ubuntu: 
    sudo apt install expect unzip xvfb xauth x11-utils dbus-x11
    Без expect и xprop запуск роботов невозможен: при отсутствии xprop виртуальный экран считается неработающим, и запуск завершается без сообщения в интерфейсе. команда which expect Xvfb xauth xprop dbus-launch выводит пять путей
  3. Убедитесь, что машина подготовлена для робота: установлены графическая оболочка и Xvfb, создан пользователь ОС для робота. Подготовка выполняется по инструкции робота. Пользователя робота включите в группу агента и создайте в его домашнем каталоге каталог данных приложений, если его нет: 
    sudo usermod -aG primo-rpa <пользователь робота>
sudo -u <пользователь робота> mkdir -p /home/<пользователь робота>/.local/share
    Каталог ~/.local/share создаётся при первом входе пользователя в графическую оболочку. У пользователя, созданного командой useradd и ни разу не входившего в систему, каталога нет, и робот завершается при старте.
  4. Создайте каталоги агента, данных агента и роботов, распакуйте архив и назначьте владельцем каталогов пользователя агента: 
    sudo mkdir -p /opt/Primo/Agent /opt/Primo/AgentData /opt/LTools
sudo unzip primo-rpa-orchestrator-agent-<версия>-linux.zip -d /opt/Primo/Agent
sudo chown -R agent:primo-rpa /opt/Primo/Agent /opt/Primo/AgentData /opt/LTools
sudo chmod +x /opt/Primo/Agent/Primo.Orchestrator.Agent /opt/Primo/Agent/LTools.Orchestrator.Agent.Runner /opt/Primo/Agent/launch-as-user.expect
  5. Предоставьте агенту права sudo без пароля: создайте файл /etc/sudoers.d/primo-agent командой sudo visudo -f /etc/sudoers.d/primo-agent со следующим содержимым: 
    agent ALL=(root) NOPASSWD: /usr/bin/systemd-run -G --uid=agent --gid=primo-rpa --property=EnvironmentFile=/dev/shm/agent-*-env /opt/Primo/Agent/launch-as-user.expect
agent ALL=(root) NOPASSWD: /usr/bin/systemd-run -G --unit=primo-robot-* --uid=agent --gid=primo-rpa --property=EnvironmentFile=/dev/shm/agent-*-env /opt/Primo/Agent/launch-as-user.expect
agent ALL=(root) NOPASSWD: /usr/bin/systemctl stop primo-robot-*.service
agent ALL=(root) NOPASSWD: /usr/sbin/reboot
    Вторая и третья строки позволяют агенту запускать робота именованным юнитом и останавливать зависший запуск. sudo -l -U agent показывает четыре команды
  6. Включите linger: sudo loginctl enable-linger agent.
  7. Проверьте /opt/Primo/Agent/appsettings.ProdLinux.json:
    • Agent:DataPath — каталог данных агента, в архиве задан /opt/Primo/AgentData;
    • DeployRobot:RobotsPath — каталог роботов, в архиве задан /opt/LTools;
    • AgentCommands:Session — полный путь к команде, которая запускает графический сеанс. В архиве указано /usr/bin/mate-session — значение для РЕД ОС. Для другой ОС замените его: Astra Linux — /usr/bin/fly-wm --execOnly {}, CentOS — /usr/bin/gnome-session, Ubuntu с оболочкой Openbox — /usr/bin/openbox-session. Если строка удалена, для Astra Linux, РЕД ОС и CentOS значение подставляется автоматически.
  8. Откройте порт 5002/tcp на файерволе машины, если файервол включён. Для ufw: sudo ufw allow 5002/tcp.
  9. Установите юнит агента. Основной вариант — пользовательский юнит пользователя agent: файл Primo.Orchestrator.Agent.user.service из архива скопируйте под именем Primo.Orchestrator.Agent.service и запустите: 
    sudo -u agent mkdir -p /home/agent/.config/systemd/user
sudo -u agent cp /opt/Primo/Agent/Primo.Orchestrator.Agent.user.service /home/agent/.config/systemd/user/Primo.Orchestrator.Agent.service
sudo -u agent XDG_RUNTIME_DIR=/run/user/$(id -u agent) systemctl --user daemon-reload
sudo -u agent XDG_RUNTIME_DIR=/run/user/$(id -u agent) systemctl --user enable --now Primo.Orchestrator.Agent
    Другой вариант — системный юнит Primo.Orchestrator.Agent.service (работает от User=agent) в /etc/systemd/system/. curl -k https://localhost:5002/api/Version печатает версию агента; в журнале (sudo -u agent XDG_RUNTIME_DIR=/run/user/$(id -u agent) journalctl --user -u Primo.Orchestrator.Agent) нет предупреждений «the launch of robots is impossible»

До регистрации машины в Оркестраторе агент каждые несколько секунд записывает в журнал ошибку «Не задан BaseUrl Оркестратора». Это штатное поведение; после регистрации запись прекращается.

При запуске агент проверяет доступность sudo, наличие expect, права на исполнение launch-as-user.expect и команды сеанса, разрешение на вызов systemd-run в sudoers, существование пользователя и группы. По каждому нарушению в журнал записывается отдельное предупреждение.

Работа агента без root: учётная запись и требования

Агент в обоих вариантах работает от Agent:UserName (по умолчанию agent), различается только способ запуска: системный менеджер (User=agent) или менеджер самого agent. Работа агента без root поддержана с версии 1.24.1.

  • Обновление агента из Оркестратора (AgentUpdater) останавливает и запускает агент командой systemctl --user stop|start Primo.Orchestrator.Agent. Поэтому основной вариант — пользовательский юнит под этим именем.
  • Для пользователя агента нужен linger, как и для служб.
  • Права через sudo без пароля агенту нужны в обоих вариантах: /usr/bin/systemd-run … /opt/Primo/Agent/launch-as-user.expect (запуск роботов) и /usr/sbin/reboot (перезагрузка машины из Оркестратора).
  • В обоих юнитах агента задано UMask=0002; в пользовательском нет Restart=always.

Как перевести уже установленный агент с системного юнита на пользовательский — Переход с root на работу без root.

Регистрация машины в Оркестраторе

  1. В интерфейсе Оркестратора откройте Настройки → Система → Машины роботов и нажмите Добавить машину.
  2. Заполните Наименование и IP/DNS; при необходимости — Работающие роботы (макс). Для Linux-машины включите Linux — после сохранения это поле не меняется. Для Windows можно включить Удерживать RDP-сессию в консоли и указать RDP-пользователь и Пароль.
  3. Сохраните. в колонке Доступна появилась дата проверки доступности, в колонке Версия агента — версия

Обновление агента

Загрузите новый дистрибутив в Настройки → Система → Дистрибутивы агента (Добавить дистрибутив Агента), затем на странице Машины роботов выберите машины и нажмите Обновить выбранные. Утилита обновления AgentUpdater для Windows и Linux входит в архив WebApi.
