Машины роботов и агент

Применимо: 1.26.9WindowsLinux

На каждую машину, где будут работать роботы, ставится агент Оркестратора. Через него WebApi разворачивает и запускает роботов. После установки машину регистрируют в UI4.

Как агент связан с Оркестратором

  • Агент слушает 5002 по HTTPS; к нему обращается WebApi (Tenants:Agent:Port, Tenants:Agent:Https).
  • Адрес Оркестратора агент узнаёт из заголовка orchestrator-url в запросах WebApi (значение RobotDeployment:OrchBaseUrl). Задавать Orchestrator:BaseUrl в конфиге агента не обязательно.
  • Пока WebApi ни разу не обратился к агенту, /health/readiness агента отвечает Unhealthy — это нормально до регистрации машины.

Установка агента

Вкладка с вашей ОС откроется сама: страница определяет систему по браузеру. Если ставите агент на другую машину — переключите вкладку.

Что нужно: архив primo-rpa-orchestrator-agent-<версия>-windows.zip, PowerShell от имени администратора.

  1. Откройте порт агента: 
    New-NetFirewallRule -Name "Primo Agent (5002)" -DisplayName "Primo Agent (5002)" -Profile "Private, Domain, Public" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 5002
    правило Primo Agent (5002) есть в брандмауэре
  2. Задайте окружение: 
    [System.Environment]::SetEnvironmentVariable("ASPNETCORE_ENVIRONMENT", "ProdWin", [System.EnvironmentVariableTarget]::Machine)
  3. Распакуйте архив в C:\Primo\Agent и при необходимости поправьте appsettings.ProdWin.json. Каталог роботов по умолчанию — C:\LTools (DeployRobot:RobotsPath).
  4. Зарегистрируйте и запустите службу: 
    New-Service -Name "Primo.Orchestrator.Agent" -BinaryPathName "C:\Primo\Agent\Primo.Orchestrator.Agent.exe" -DisplayName "Primo.Orchestrator.Agent" -StartupType Automatic
Start-Service "Primo.Orchestrator.Agent"
    Get-Service Primo.Orchestrator.Agent — Running; https://localhost:5002/api/Version возвращает версию агента

Роботов агент запускает заданиями Планировщика заданий Windows от имени пользователя робота.

Что нужно: архив primo-rpa-orchestrator-agent-<версия>-linux.zip (в нём агент, LTools.Orchestrator.Agent.Runner, appsettings.Runner.json, launch-as-user.expect и юниты), права root на подготовку.

  1. Создайте группу и пользователя агента (имена по умолчанию; другие — укажите в Agent:GroupName и Agent:UserName): 
    sudo groupadd primo-rpa
sudo useradd -g primo-rpa -m -s /bin/bash agent
    id agent показывает группу primo-rpa
  2. Установите expect и unzip. На Ubuntu и Astra Linux: sudo apt install expect unzip. Без expect (/usr/bin/expect) роботы не запустятся.
  3. Убедитесь, что машина подготовлена под робота: на ней стоят графическая оболочка и Xvfb, создан пользователь ОС для робота. Это делают по инструкции робота. Пользователя робота включите в группу агента: sudo usermod -aG primo-rpa <пользователь робота>.
  4. Создайте каталоги агента, данных агента и роботов, распакуйте архив и отдайте каталоги агенту: 
    sudo mkdir -p /opt/Primo/Agent /opt/Primo/AgentData /opt/LTools
sudo unzip primo-rpa-orchestrator-agent-<версия>-linux.zip -d /opt/Primo/Agent
sudo chown -R agent:primo-rpa /opt/Primo/Agent /opt/Primo/AgentData /opt/LTools
sudo chmod +x /opt/Primo/Agent/Primo.Orchestrator.Agent /opt/Primo/Agent/LTools.Orchestrator.Agent.Runner /opt/Primo/Agent/launch-as-user.expect
  5. Дайте агенту права sudo без пароля: создайте файл /etc/sudoers.d/primo-agent командой sudo visudo -f /etc/sudoers.d/primo-agent с таким содержимым: 
    agent ALL=(root) NOPASSWD: /usr/bin/systemd-run -G --uid=agent --gid=primo-rpa --property=EnvironmentFile=/dev/shm/agent-*-env /opt/Primo/Agent/launch-as-user.expect
agent ALL=(root) NOPASSWD: /usr/sbin/reboot
    sudo -l -U agent показывает обе команды
  6. Включите linger: sudo loginctl enable-linger agent.
  7. Проверьте /opt/Primo/Agent/appsettings.ProdLinux.json:
    • Agent:DataPath — каталог данных агента, в архиве задан /opt/Primo/AgentData;
    • DeployRobot:RobotsPath — каталог роботов, в архиве задан /opt/LTools;
    • AgentCommands:Session — полный путь к команде, которая запускает графический сеанс. В архиве записано /usr/bin/mate-session — это значение для РЕД ОС. Для другой ОС замените его: Astra Linux — /usr/bin/fly-wm --execOnly {}, CentOS — /usr/bin/gnome-session, Ubuntu с оболочкой Openbox — /usr/bin/openbox-session. Если строку удалить, для Astra Linux, РЕД ОС и CentOS агент подставит значение сам.
  8. Откройте порт 5002/tcp на файерволе машины, если файервол включён. Для ufw: sudo ufw allow 5002/tcp.
  9. Установите юнит агента. Основной вариант — пользовательский юнит пользователя agent: файл Primo.Orchestrator.Agent.user.service из архива скопируйте под именем Primo.Orchestrator.Agent.service и запустите: 
    sudo -u agent mkdir -p /home/agent/.config/systemd/user
sudo -u agent cp /opt/Primo/Agent/Primo.Orchestrator.Agent.user.service /home/agent/.config/systemd/user/Primo.Orchestrator.Agent.service
sudo -u agent XDG_RUNTIME_DIR=/run/user/$(id -u agent) systemctl --user daemon-reload
sudo -u agent XDG_RUNTIME_DIR=/run/user/$(id -u agent) systemctl --user enable --now Primo.Orchestrator.Agent
    Другой вариант — системный юнит Primo.Orchestrator.Agent.service (работает от User=agent) в /etc/systemd/system/. curl -k https://localhost:5002/api/Version печатает версию агента; в журнале (sudo -u agent XDG_RUNTIME_DIR=/run/user/$(id -u agent) journalctl --user -u Primo.Orchestrator.Agent) нет предупреждений «the launch of robots is impossible»

Пока машина не зарегистрирована в Оркестраторе, агент каждые несколько секунд пишет в журнал ошибку «Не задан BaseUrl Оркестратора» — это нормально и прекращается после регистрации.

При старте агент сам проверяет: доступен ли sudo, есть ли expect, исполняемы ли launch-as-user.expect и команда сеанса, разрешён ли в sudoers вызов systemd-run, существуют ли пользователь и группа. Каждая проблема — отдельное предупреждение в журнале.

Агент без root: от кого работает и что ему нужно

Агент в обоих вариантах работает от Agent:UserName (по умолчанию agent), разница только в том, кто его запускает: системный менеджер (User=agent) или менеджер самого agent. Работа агента без root поддержана с версии 1.24.1.

  • Обновление агента из Оркестратора (AgentUpdater) останавливает и запускает агент командой systemctl --user stop|start Primo.Orchestrator.Agent. Поэтому основной вариант — пользовательский юнит под этим именем.
  • Для пользователя агента нужен linger, как и для служб.
  • Права через sudo без пароля агенту нужны в обоих вариантах: /usr/bin/systemd-run … /opt/Primo/Agent/launch-as-user.expect (запуск роботов) и /usr/sbin/reboot (перезагрузка машины из Оркестратора).
  • В обоих юнитах агента задано UMask=0002; в пользовательском нет Restart=always.

Как перевести уже установленный агент с системного юнита на пользовательский — Переход с root на работу без root.

Регистрация машины в Оркестраторе

  1. В UI4 откройте Настройки → Система → Машины роботов и нажмите Добавить машину.
  2. Заполните Наименование и IP/DNS; при необходимости — Работающие роботы (макс). Для Linux-машины включите Linux — после сохранения это поле не меняется. Для Windows можно включить Удерживать RDP-сессию в консоли и указать RDP-пользователь и Пароль.
  3. Сохраните. в колонке Доступна появилась дата проверки доступности, в колонке Версия агента — версия

Обновление агента

Загрузите новый дистрибутив в Настройки → Система → Дистрибутивы агента (Добавить дистрибутив Агента), затем на странице Машины роботов выберите машины и нажмите Обновить выбранные. Утилита обновления AgentUpdater для Windows и Linux вшита в архив WebApi.
