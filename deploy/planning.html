Планирование установки

Применимо: 1.26.9WindowsLinuxDocker

Что решить до того, как распаковывать дистрибутивы: где будут работать службы, какая СУБД, какие порты открыть и под какими учётными записями всё запускать.

Из чего состоит Оркестратор

Оркестратор — набор отдельных служб. Каждая поставляется своим архивом для Windows и для Linux (суффикс -linux) и в Docker — своим образом.

СлужбаАрхивЧто делает
WebApiWebApi, WebApi-linuxОсновной API, работает с БД ltools, ltoolsidentity, ltoolslicense, ltoolsltwrepo, обращается к агентам и роботам.
UIархив UI4 (отдельный репозиторий)Веб-интерфейс, раздаётся nginx; nginx же проксирует запросы к службам.
MachineInfoMachineInfoДанные об оборудовании для лицензирования; к нему обращается WebApi (License:MachineInfoUrl).
RobotLogsRobotLogsПринимает журналы роботов, БД ltoolslogs.
Queues, LicensesQueues, LicensesПринимают уведомления и ответы по лицензиям от роботов.
States, Notifications, AnalyticодноимённыеСостояния, почтовые оповещения, аналитика (БД ltoolsanalytic).
NuGet2NuGet2NuGet-сервер (БД ltoolsnuget).
RDP2RDP2Поддержка RDP-сессий; в Docker-поставку не входит.
LogEventsWebhook, ArcSightодноимённыеПередача событий во внешние системы. Можно поставить позже.
AgentAgent, Agent-linuxСтавится на каждую машину робота.
PasswordEncryptorPasswordEncryptorУтилита шифрования паролей для конфигурации.

Все службы обмениваются сообщениями через RabbitMQ. Архивы собираются как self-contained: отдельно ставить .NET на сервер не нужно.

Что решить до установки

  1. Вариант развертывания: Docker, службы Linux или службы Windows с nginx; один сервер или несколько.
  2. СУБД: PostgreSQL или MS SQL Server. В Docker-поставке — только PostgreSQL.
  3. Железо под ожидаемое число роботов и RDP-сессий.
  4. Сеть: адрес, по которому Оркестратор увидят роботы, порты между службами, агентами и роботами.
  5. Учётные записи: от кого работают службы, агент, роботы; пользователи СУБД и RabbitMQ.
  6. Сертификат для HTTPS на nginx.

После планирования пройдите чек-лист подготовки.

Назначение States, Analytic, ArcSight описано по именам проектов и старым докам — сверить формулировки с разработкой. Архив UI в azure/build.ps1 не собирается (UI собирается из репозитория UI4) — уточнить имя архива UI в поставке 1.26.9.

Источники: azure/build.ps1 (состав архивов, --self-contained true); docker/ubuntu/*.Dockerfile (имена БД DbConnection__Items__*__DbName, DBVendor); Orchestrator/*.Migrations.MSSQL, *.Migrations.Postgres; nginx/nginx.linux.conf; руководство 1.25.7, разделы «Комплект поставки», «Установка компонентов Оркестратора».
