Что должно быть на руках

Отмечайте готовое — отметки сохраняются в вашем браузере.

Вы сами

  • Архивы под ваш вариант установки скачаны — список и адреса на странице Дистрибутивы.
  • Дистрибутив робота — его загружают в Оркестратор после установки.
  • Утилита PasswordEncryptor — чтобы зашифровать пароли для конфигов.
  • Тестовый RPA-проект — понадобится на шаге Проверка установки.
  • Известно, кому отправлять запрос на лицензию: запрос формируется в интерфейсе уже установленного Оркестратора и отправляется вендору — см. Первый запуск.

Администратор серверов

  • Сервер или серверы под выбранный вариант и ресурсы, с поддерживаемой версией ОС — см. Совместимость.
  • У вас есть права администратора на этих серверах.
  • Время на серверах и машинах роботов синхронизировано.
  • Установлен Docker Engine с плагином docker compose.
  • Установлен nginx из репозитория вашего дистрибутива (apt или dnf).
  • RabbitMQ установлен, для служб создан пользователь. В Docker RabbitMQ уже есть в compose-файле.
  • Машины роботов готовы; на машинах с Linux установлены пакет expect и sudo.
  • Созданы учётные записи ОС из таблицы Что заказать: для служб, для агента, для роботов.

Администратор БД

  • PostgreSQL установлен. В Docker PostgreSQL 14 уже есть в compose-файле. Вместо него можно MS SQL Server — только для служб на Windows Server.
  • Базы ltools, ltoolsidentity, ltoolslicense, ltoolsltwrepo, ltoolslogs, ltoolsanalytic, ltoolsnuget созданы — или пользователю миграций дано право создавать БД.
  • Созданы пользователь для работы и пользователь для миграций (может быть один).

Сетевой администратор

  • Есть внешний адрес Оркестратора — DNS-имя или IP, по которому его увидят пользователи, роботы и агенты.
  • Открыты порты по таблице Что открыть между машинами.
  • Если нужны письма с оповещениями — известны адрес и порт почтового сервера и учётная запись для отправки.

Служба безопасности

  • Выпущен сертификат на внешнее имя Оркестратора, есть файл сертификата и закрытый ключ. Сертификат, который лежит в репозитории рядом с конфигами nginx, выпущен для внутреннего стенда и для промышленной установки не подходит.
  • Для промышленной установки заданы свои значения PRIMOSALT (соль шифрования паролей в конфигах) и PRIMOSIGNINGKEY (ключ подписи токенов) — одинаковые на всех службах и агентах. Задать их нужно до того, как шифровать пароли утилитой.
