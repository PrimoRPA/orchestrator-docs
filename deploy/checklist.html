Дистрибутивы

Где скачать — Дистрибутивы.

  • Архивы служб под вашу ОС: для Windows — без суффикса, для Linux — *-linux.zip. Для Docker — docker-compose.yml и доступ к реестру образов.
  • Архив UI4.
  • Конфиг nginx под вариант: nginx.linux.conf, nginx.win.conf или nginx.docker.conf.
  • Архив агента: Agent (Windows) или Agent-linux (Linux).
  • Дистрибутив робота — его загружают в Оркестратор после установки.
  • Утилита PasswordEncryptor — чтобы зашифровать пароли для конфигов.
  • Тестовый RPA-проект — понадобится на шаге Проверка установки.

Серверы и ОС

  • Сервер(ы) под выбранный вариант и ресурсы.
  • Docker: Docker Engine с плагином docker compose (в compose используются depends_on с condition и healthcheck.start_interval).
  • Linux без Docker: nginx из репозитория дистрибутива (apt или dnf); от пакета нужны /usr/sbin/nginx и /etc/nginx/mime.types.
  • Машины роботов с ОС под агент; на Linux — пакет expect (/usr/bin/expect) и sudo.

СУБД

  • PostgreSQL. MS SQL Server — только для служб на Windows Server. В Docker PostgreSQL 14 идёт в compose.
  • Базы: ltools, ltoolsidentity, ltoolslicense, ltoolsltwrepo, ltoolslogs, ltoolsanalytic, ltoolsnuget. Либо создайте их заранее, либо дайте пользователю миграций право создавать БД.
  • Пользователь для работы и пользователь для миграций (может быть один).

RabbitMQ

  • Сервер RabbitMQ (в Docker — образ rabbitmq:3-management в compose), порт 5672.
  • Пользователь и пароль для служб.

Сеть и DNS

  • Внешний адрес Оркестратора (DNS-имя или IP), по которому его увидят пользователи, роботы и агенты. Он прописывается в RobotDeployment:OrchBaseUrl, RobotDeployment:RobotLogsBaseUrl, NuGet:NuGetBaseUrl, RDP:RdpBaseUrl.
  • Открыты порты по таблице Порты и сетевой трафик: 44392 к nginx, 5002 от WebApi к агентам, порты роботов от WebApi к машинам роботов.
  • SMTP-сервер для оповещений (адрес, порт, учётная запись) — если нужны письма.

Сертификаты

  • Сертификат и ключ для nginx. Конфиги ждут файлы cert1.crt и cert1.rsa рядом с nginx.conf.
  • Выпустите сертификат на внешнее имя Оркестратора. Сертификат, лежащий в репозитории рядом с конфигами nginx, выпущен для внутреннего стенда и для продуктива не подходит.

Старые доки: в поставке «самоподписанный сертификат» cert1.crt/cert1.rsa. В выгрузке nginx/certificates/cert1.crt выпущен внутренним УЦ на имя стенда разработки. Уточнить, что реально кладётся в поставку.

Учётные записи

  • Пользователь ОС для служб на Linux (службы работают без root) — см. Учётные записи и права служб.
  • На машинах роботов Linux: пользователь агента (agent) и группа primo-rpa, пользователи роботов.
  • На машинах роботов Windows: пользователи, от имени которых будут запускаться роботы (RDP-пользователи).

Секреты

  • Решите, задаёте ли свои PRIMOSALT (соль шифрования паролей в конфигах) и PRIMOSIGNINGKEY (ключ подписи токенов). Для промышленной установки задавайте свои — одинаковые на всех службах и агентах, и до шифрования паролей утилитой.

Лицензии

  • Контакт вендора для обмена файлами: запрос на лицензию формируется в UI уже установленного Оркестратора и отправляется вендору. См. Первый запуск.
