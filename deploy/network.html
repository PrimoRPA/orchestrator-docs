Порты и сетевой трафик

Применимо: 1.26.9WindowsLinuxDocker

Какие порты слушают службы Оркестратора, агент и робот, и кто к кому обращается. По этой таблице открывайте порты на файерволах.

Порты служб Оркестратора

Порты — значения из поставки по умолчанию. Для установки на Windows и Linux они совпадают (одинаковые upstream в nginx.win.conf и nginx.linux.conf).

Службы без маршрута в nginx (Analytic, States, Notifications, LogEventsWebhook) получают работу через RabbitMQ; их HTTP-порт нужен только для /health.

Агент на машине робота5002HTTPSWebApi. Порт и протокол со стороны WebApi — Tenants:Agent:Port (по умолчанию 5002) и Tenants:Agent:Https (true)

В обратную сторону агент и роботы ходят только на внешний адрес Оркестратора (nginx, 44392). Этот адрес WebApi передаёт им из RobotDeployment:OrchBaseUrl и RobotDeployment:RobotLogsBaseUrl; агент получает его в заголовке orchestrator-url, если в его конфиге не задан Orchestrator:BaseUrl.

Docker

В docker-compose.yml на хост опубликованы только: 44392 (UI), 8081 (NuGet2), 5432 (PostgreSQL), 15672 (консоль RabbitMQ). Остальные службы общаются внутри сети compose по именам (web-api:5001 и т. д.).

Если PostgreSQL и консоль RabbitMQ не должны быть видны из сети — уберите их из ports в compose или закройте файерволом.

Диапазон портов роботов в коде не найден: порт робота хранится в карточке робота и приходит от агента при развертывании. Старые доки называли диапазон 8000–9000 — подтвердить.

Привязка Kestrel служб на Windows/Linux задаётся в appsettings.*.json, которых нет в выгрузке. Порты в таблице взяты из Kestrel__EndPoints__*__Url в Dockerfile и из upstream в конфигах nginx — сверить с appsettings.ProdLinux.json/ProdWin.json поставки. В Dockerfile EXPOSE 8080 10052 не совпадает с фактическим портом Kestrel (5001, 56748…) — на работу не влияет, но может путать.

Старая таблица портов упоминала 3389 для RDP2, 389/636 (LDAP/LDAPS). В коде nginx RDP2 доступен на 5102; порты LDAP и RDP до машин роботов описать на странице интеграций/RDP после проверки.
