Какие службы ставить

Оркестратор — набор служб. Большинство нужно всегда, несколько ставятся только под конкретную задачу. В Docker-поставке все обязательные службы уже есть в compose.

Нужно всегдаЗачем
PostgreSQL / MS SQL Serverбазы данных Оркестратора
RabbitMQсобытия между службами и очередь проектов
nginx с UI4веб-интерфейс; единственный адрес, открытый наружу
WebApiосновная служба: проекты, роботы, задания, пользователи, команды агентам
MachineInfoданные об оборудовании сервера для лицензии
RobotLogsжурналы роботов
States, Notificationsсостояния роботов и почтовые оповещения
Analyticаналитика и дашборды
Queues, Licensesуведомления и лицензии для attended- и DPA-роботов
NuGet2репозиторий пакетов для Студии
Агентна каждой машине, где будут работать роботы
RDP2если роботы работают на Windows: RDP-сессии роботов и консоль сессии в браузере; удобно ставить на отдельную машину
По необходимостиКогда нужна
LogEventsWebhookсобытия Оркестратора нужно передавать во внешнюю систему по HTTP; можно поставить позже
ArcSightсобытия нужно выгружать в SIEM ArcSight
MCP Serverс Оркестратором будут работать ИИ-клиенты; в поставке 1.26.9 — только в Docker-шаблоне для Ubuntu, см. MCP Server

Все службы по умолчанию ставятся на один сервер. Как разнести их по нескольким — Выбор варианта развертывания → Один сервер или несколько. Полный список служб с архивами и базами данных — Компоненты и службы.

Какие из «нужно всегда» на деле можно не ставить (например, Analytic без дашбордов, Notifications без почты, NuGet2 без публикации пакетов) — уточнить у разработки.

Назначение States, Analytic, ArcSight описано по именам проектов и старым докам — сверить формулировки с разработкой. Архив UI в azure/build.ps1 не собирается (UI собирается из репозитория UI4) — уточнить имя архива UI в поставке 1.26.9.
