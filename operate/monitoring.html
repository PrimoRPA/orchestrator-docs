Мониторинг и метрики

Применимо: 1.26.9WindowsLinuxDocker

Каждая служба Оркестратора умеет отдавать метрики в Prometheus или Zabbix. Здесь — как включить сбор, какой адрес указать в системе мониторинга и какие метрики есть.

Как это устроено

Служба сама ничего не отправляет. Она открывает отдельный порт и ждёт, когда к ней обратится Prometheus (HTTP, путь /metrics) или сервер Zabbix (пассивная проверка по протоколу агента Zabbix). Провайдер выбирается в секции Monitoring конфига каждой службы. По умолчанию провайдер не задан — мониторинг выключен, в журнал службы пишется предупреждение Monitoring service is disabled.

Секция Monitoring есть у служб: WebApi, RobotLogs, States, Queues, Notifications, MachineInfo, Analytic, Licenses, LogEventsWebhook, ArcSight, RDP2, а также у Агента на машинах роботов.

Параметры

ПараметрНазначениеПо умолчанию
Monitoring:ProviderPrometheus, Zabbix или пустая строка (выключено). Другое значение — ошибка в журнале службы, мониторинг выключен.""
Monitoring:PortПорт, на котором служба отвечает системе мониторинга. Значение вне 0–65535 — ошибка, мониторинг выключен.10052
Monitoring:DotNetMonitoringEnabledМетрики процесса .NET: память, сборки мусора, потоки, CPU.false
Monitoring:KestrelMonitoringEnabledМетрики встроенного веб-сервера Kestrel: подключения, очереди, TLS.false
Monitoring:NpgsqlMonitoringEnabledМетрики подключений к PostgreSQL, с меткой DbName. Для служб, которые не ходят в БД (RDP2, MachineInfo), включать незачем.false
Monitoring:IdleDurationMillisТолько WebApi: как часто (мс) пересчитывать метрики primo_orch_*, которые считаются запросами к БД. Между пересчётами отдаются прежние значения. Меньше 1000 не бывает.2000

Пример фрагмента appsettings.json любой службы:

"Monitoring": {
  "Provider": "Prometheus",
  "Port": 10052,
  "DotNetMonitoringEnabled": true,
  "KestrelMonitoringEnabled": true,
  "NpgsqlMonitoringEnabled": true,
  "IdleDurationMillis": 10000
}

В Docker-образах из k8s/*.Dockerfile мониторинг уже включён переменными окружения: Monitoring__Provider=Prometheus, Monitoring__Port=10052, порт 10052 объявлен в EXPOSE.

Если несколько служб стоят на одном сервере, задайте каждой свой Monitoring:Port — по умолчанию у всех 10052, и вторая служба не сможет открыть порт.

Подключение Prometheus

  1. Включите Provider: "Prometheus" и перезапустите службу. в журнале службы нет сообщения Monitoring service is disabled
  2. Откройте в браузере http://<хост службы>:<Monitoring:Port>/metrics. видны строки # HELP и primo_…
  3. Добавьте задание в scrape_configs Prometheus — по одному job_name на службу.

Пример конфига Prometheus лежит в поставке исходников: prometheus/prometheus.yml. Он рассчитан на локальный стенд (порты 9900–9960 на host.docker.internal) — в своей установке подставьте реальные хосты и порты.

Подключение Zabbix

При Provider: "Zabbix" служба работает как пассивный агент Zabbix на порту Monitoring:Port. На сервере Zabbix заведите узел с интерфейсом агента на этот адрес и порт.

  • Ключ элемента данных — имя метрики, например primo_rl_queue_length.
  • Для метрики с меткой значение метки пишется в квадратных скобках: db_client_connections_usage[ltoolslogs]. Метка без скобок — значение без метки.
  • Ключ agent.ping всегда возвращает 1 — удобно для проверки доступности.
  • Неизвестный ключ возвращает ZBX_NOTSUPPORTED.

Значение метки в ключе Zabbix должно состоять из латинских букв, цифр и _ и не начинаться с цифры. Метрики WebApi размечены именем тенанта (TenantName): для тенанта с кириллицей, пробелом или дефисом в имени ключ не пройдёт проверку, Zabbix получит ZBX_NOTSUPPORTED.

Метрики служб

У каждой метрики в коде есть описание на русском (строка # HELP). Ниже — сводка; полный текст виден в ответе /metrics.

Общие метрики (если включены): dotnet_* и process_*, kestrel_*, db_client_*.

Метрики primo_orch_* считаются запросами к БД при каждом обращении Prometheus или Zabbix, но не чаще, чем раз в IdleDurationMillis. При частом опросе увеличьте этот параметр.

Grafana

Для показа отчётов Grafana внутри Оркестратора в конфиге WebApi есть секция Grafana:ReportItems — список разделов (Name) с отчётами (Name, Url, Description). В UI4 отчёты открываются в разделе «Аналитика» → «Grafana». В шаблонах nginx Grafana проксируется по пути /grafana/ на 127.0.0.1:3000. Примеры дашбордов и представлений для аналитической БД лежат в LTools.Orchestrator.Analytic/Grafana/.
