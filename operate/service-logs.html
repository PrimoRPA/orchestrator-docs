Журналы служб

Применимо: 1.26.9WindowsLinuxDocker

На странице описано, где находятся технические журналы служб Оркестратора и как изменить уровень детализации. Журнал Оркестратора и журналы роботов в UI описаны отдельно — в Событиях и Журналах.

Как устроено

Все службы (WebApi, RobotLogs, States, Queues, Notifications, MachineInfo, Analytic, Licenses, LogEventsWebhook, ArcSight, RDP2, Агент) пишут журнал через Serilog. Место и уровень записи полностью задаются секцией Serilog конфига службы. В коде пути к файлам журналов не заданы.

К каждой записи добавляется версия службы (ApplicationVersion); у WebApi — ещё идентификатор узла кластера.

ПараметрНазначениеПо умолчанию
Serilog:MinimumLevel:DefaultОбщий уровень: Verbose, Debug, Information, Warning, Error, Fatal.Information (если не задан или задан с ошибкой)
Serilog:MinimumLevel:Override:<источник>Уровень для отдельного источника, например Microsoft.—
Serilog:WriteToПриёмник записи (sink) и его параметры.—
UseHttpLoggingТолько WebApi: подробное журналирование HTTP-запросов.false

Docker

В образах поставки (k8s/*.Dockerfile) журнал пишется в консоль контейнера в формате compact JSON, уровень Warning:

Serilog__MinimumLevel__Default=Warning
Serilog__WriteTo__0__Name=Console
Serilog__WriteTo__0__Args__Formatter=Serilog.Formatting.Compact.RenderedCompactJsonFormatter,Serilog.Formatting.Compact

Просмотр: docker logs <контейнер> или kubectl logs <под>. Журналы nginx в контейнере UI также выводятся в stdout/stderr.

Linux (systemd)

Службы устанавливаются в /opt/Primo/<Служба> и запускаются с ключом --console. В unit-файлах задан SyslogIdentifier вида Primo.Orchestrator.<Служба>, поэтому всё, что служба пишет в консоль, попадает в journald:

journalctl -t Primo.Orchestrator.WebApi --since "1 hour ago"
journalctl -u Primo.Orchestrator.RobotLogs -f

Если в секции Serilog настроен вывод в файл, путь указан в Serilog:WriteTo:…:Args:path. Относительный путь считается от папки службы.

Агент на Linux-машине робота при установке скриптом k8s/agent/install.sh пишет в файл ~/primo/log/log-.txt пользователя робота: новый файл каждый день, хранятся 20 последних, уровень Warning.

Windows

Службы работают как службы Windows; рабочая папка — папка службы. Куда пишется журнал, определяется секцией Serilog в appsettings.json / appsettings.ProdWin.json.

Уровень без перезапуска

Текущие уровни доступны по HTTP и изменяются без перезапуска службы (изменение действует до перезапуска):

  • GET /loggers — список: default и все переопределения из Serilog:MinimumLevel:Override.
  • POST /loggers/<имя>/<уровень> — изменить уровень, например POST /loggers/default/Debug.

Как проверить: после POST ответ содержит новый уровень, в журнале службы появляются записи этого уровня.
