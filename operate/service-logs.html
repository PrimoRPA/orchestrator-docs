Журналы служб

Применимо: 1.26.9WindowsLinuxDocker

На странице описано, где находятся технические журналы служб Оркестратора и как изменить уровень детализации. Журнал Оркестратора и журналы роботов в UI описаны отдельно — в Событиях и Журналах.

Перед началомпройдена Проверка установки
Результатнайден журнал нужной службы, уровень детализации изменён

Как устроено

Все службы (WebApi, RobotLogs, States, Queues, Notifications, MachineInfo, Analytic, Licenses, LogEventsWebhook, ArcSight, RDP2, Агент) пишут журнал через Serilog. Место и уровень записи полностью задаются секцией Serilog конфига службы: appsettings.ProdLinux.json (Linux), appsettings.ProdWin.json (Windows) или переменные окружения контейнера (Docker). Встроенного пути к файлам журналов нет: если файловый приёмник в секции не настроен, журнал в файл не пишется.

К каждой записи добавляется версия службы (ApplicationVersion); у WebApi — ещё идентификатор узла кластера.

ПараметрНазначениеПо умолчанию
Serilog:MinimumLevel:DefaultОбщий уровень: Verbose, Debug, Information, Warning, Error, Fatal.Information (если не задан или задан с ошибкой)
Serilog:MinimumLevel:Override:<источник>Уровень для отдельного источника, например Microsoft.—
Serilog:WriteToПриёмник записи (sink) и его параметры.—
UseHttpLoggingТолько WebApi: подробное журналирование HTTP-запросов.false

Docker

В образах поставки журнал пишется в консоль контейнера в формате compact JSON, уровень Warning:

Serilog__MinimumLevel__Default=Warning
Serilog__WriteTo__0__Name=Console
Serilog__WriteTo__0__Args__Formatter=Serilog.Formatting.Compact.RenderedCompactJsonFormatter,Serilog.Formatting.Compact

Просмотр на Docker-хосте: docker logs <контейнер> (в Kubernetes — kubectl logs <под>). Журналы nginx в контейнере UI также выводятся в stdout/stderr.

Linux (systemd)

Службы устанавливаются в /opt/Primo/<Служба> и запускаются с ключом --console. С поставочным appsettings.ProdLinux.json журнал пишется в два места:

  • Файл /opt/Primo/<Служба>/Logs/log-.txt (к имени добавляется дата): новый файл каждый день, хранятся 20 последних. У Агента на машине робота — /opt/Primo/Agent/Logs/log-.txt.
  • Консоль, то есть journald: в юнитах задан SyslogIdentifier вида Primo.Orchestrator.<Служба>.

Уровень в поставочных конфигах — Warning; у RDP2 — Error, у Notifications — Information.

Просмотр journald, если службы работают без root (под пользователем служб orch-user):

journalctl --user -u Primo.Orchestrator.WebApi --since "1 hour ago"
journalctl --user -u Primo.Orchestrator.RobotLogs -f

Если службы работают от root (под учётной записью с правом sudo):

sudo journalctl -u Primo.Orchestrator.WebApi --since "1 hour ago"
sudo journalctl -t Primo.Orchestrator.RobotLogs -f

Путь к файлу задаётся в параметре path файлового приёмника в Serilog:WriteTo. Относительный путь считается от папки службы.

Windows

Службы работают как службы Windows; рабочая папка — папка службы. Куда пишется журнал, определяется секцией Serilog в appsettings.ProdWin.json: путь к файлу — параметр path файлового приёмника в Serilog:WriteTo.

Изменение уровня без перезапуска

Текущие уровни доступны по HTTP и изменяются без перезапуска службы (изменение действует до перезапуска):

  • GET /loggers — список: default и все переопределения из Serilog:MinimumLevel:Override.
  • POST /loggers/<имя>/<уровень> — изменить уровень, например POST /loggers/default/Debug.

Как проверить: после POST ответ содержит новый уровень, в журнале службы появляются записи этого уровня.
