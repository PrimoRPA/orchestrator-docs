MCP Server

Применимо: 1.26.9Docker

MCP Server — отдельная служба, через которую внешние ИИ-клиенты работают с Оркестратором по протоколу MCP. В поставке 1.26.9 она есть только в Docker-шаблоне для UbuntuВ 1.26.7 LTS она поставляется отдельными архивами для Windows и Linux (primo-rpa-mcp-1.26.7.1) и доступна через nginx по пути /mcp.

Что это за служба

MCP Server работает от имени учётной записи Оркестратора, заданной в его настройках. Внешние клиенты подключаются к нему по API-ключу из списка Mcp:ApiKeys.

Параметры

Настройки задаются переменными окружения. Файл appsettings.ProdLinux.json из архива в образ не попадает и заменяется пустым.

Параметр (переменная окружения)НазначениеПо умолчанию в образе
Orchestrator__BaseUrlАдрес WebApi, к которому обращается MCP Server.http://web-api:5001/
Orchestrator__UserNameУчётная запись Оркестратора, от имени которой работает служба.admin
Orchestrator__PasswordПароль этой учётной записи.пусто
Orchestrator__IgnoreSslErrorsИгнорировать ошибки SSL при обращении к Оркестратору.false
Mcp__ApiKeys__0API-ключ для внешних клиентов. Ключей может быть несколько: Mcp__ApiKeys__1 и т. д.пусто
Kestrel__EndPoints__InternalHttp__UrlАдрес, который слушает служба.http://*:5080
ASPNETCORE_ENVIRONMENTОкружение.ProdLinux

В compose-шаблоне значения для службы берутся из x-secrets: mcp-orch-user, mcp-orch-pass, mcp-api-key. Там же задаётся TZ.

nginx

Блок для MCP Server уже есть во всех трёх конфигах nginx (nginx.docker.conf, nginx.linux.conf, nginx.win.conf):

upstream mcp { server mcp:5080; }        # в Docker; на Windows и Linux — 127.0.0.1:5080

location /mcp {
  proxy_pass http://mcp;      # без URI: путь передаётся как есть
  proxy_buffering off;        # ответ на tools/call идёт потоком SSE
  proxy_read_timeout 180s;    # больше таймаута диспетчера MCP Server (120 с)
}

Все пути службы начинаются с /mcp. Если меняете конфиг, не включайте буферизацию и не уменьшайте proxy_read_timeout ниже 120 секунд.

Как включить (Docker, Ubuntu)

  1. В x-secrets compose-файла задайте mcp-orch-user и mcp-orch-pass — учётную запись Оркестратора для службы. в файле нет значений из примера
  2. Задайте mcp-api-key — ключ, который вы выдадите ИИ-клиентам. ключ не совпадает с паролями из x-secrets
  3. Проверьте, что у сервиса mcp указан образ, а не заготовка image: <mcp>. в строке image: есть реестр и тег
  4. Запустите службу: 
    docker compose up -d mcp
    docker compose ps показывает mcp в состоянии healthy
  5. Проверьте доступ через nginx: откройте https://<сервер>:44392/mcp/health. ответ 200; 503 значит, что MCP Server не может достучаться до Оркестратора — проверьте учётную запись и Orchestrator__BaseUrl

В шаблоне служба работает от имени admin. Все действия ИИ-клиентов в Оркестраторе выполняются с правами этой учётной записи.
