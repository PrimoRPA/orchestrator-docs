ПараЧто известно из кода
Службы сервераВсе службы (WebApi, RobotLogs, States, Notifications, Analytic, Licenses, Queues, MachineInfo, LogEventsWebhook, NuGet2, RDP2) и агент собираются с одной версией, в этом релизе 1.26.9. Ставьте их одной версией. Состав служб — на странице «Общие сведения».
Сервер × UI4UI4 выпускается отдельно, с номером 4.ГГ.М.x. Релизу 1.26.9.0 соответствует UI4 из ветки releases/v4.26.9.1.
Сервер × агентАвтообновление агента из Оркестратора принимает только дистрибутив агента версии 1.24.8.0 и выше и только той же ОС, что и машина. Утилита обновления (AgentUpdater) берётся из пакета WebApi, поэтому сначала обновляют сервер. Отдельной проверки версии уже установленного агента при обычной работе нет.
Сервер × СтудияСтудия занимает, продлевает и освобождает лицензию через WebApi (api/Licenses/{key}/TakeAvailableStudioLicense, KeepAliveStudio, ReleaseStudioLicense). В запросе Студия может передать свою версию; поля платформы нет, поэтому Студию Windows и Студию Linux Оркестратор не различает. Проверку версии см. в разделе «Ограничение версии Студии».
Сервер × роботДистрибутив робота загружается в Оркестратор и разворачивается агентом: архив LTools.Robot.x64.zip или LTools.Robot.x86.zip, исполняемый файл Primo.Robot (Primo.Robot.exe на Windows). Агент обращается к роботу по https://<IP>:<порт>/LTools.Robot/RobotService/api/…. Версию дистрибутива Оркестратор не отклоняет, но отдельные функции включает только с определённой версии робота (таблица ниже).
Сервер × Студия и робот: методы APIСтарые методы, которыми пользуются робот и Студия, оставлены рядом с новыми: например, api/ExchangeQueues/ReadItems, v2/ReadItems и v3/ReadItems; api/Assets/GetByName (помечен Obsolete) и v2/GetByName; TakeAvailableAttendedRobotLicense и TakeAvailableAttendedRobotLicense/v2. В 1.26.9 в фильтр чтения очереди добавлен список статусов EventTypes, старое поле EventType оставлено. Это наблюдение по коду, а не гарантия: новая функция робота или Студии может требовать метода, которого нет в более старом Оркестраторе.
Сервер × пакетыNuGet2 построен на BaGet: фид по протоколу NuGet v3 (v3/index.json), публикация пакета — api/v2/package.
Сервер × Robot RunnerОтдельного клиента с именем Robot Runner в коде Оркестратора нет. Есть роль LimitedRobotRunner и признак роли с тем же именем; связь с продуктом Robot Runner в коде не описана.

Ограничение версии Студии — настройка, а не совместимость

Секция StudioVersionChecker в WebApi задаёт минимальную версию Студии, которой Оркестратор выдаёт лицензию. Это ограничение, которое ставит администратор. Оно не говорит, какие версии Студии совместимы с Оркестратором.

ПараметрНазначениеПо умолчанию
StudioVersionChecker:MinimumStudioVersionМинимальная версия Студии в формате 1.23.8.4. Если не задана, проверка выключена (в журнал пишется предупреждение).не задано
StudioVersionChecker:StudioVersionExceptionBehaviorTypeЧто делает Студия при отказе: 0 — закрывается молча, 1 — показывает сообщение и закрывается, 2 — только показывает сообщение. Значение вне 0–2 заменяется на 1.0
  • Если версия Студии ниже порога, WebApi отвечает 409 с текстом «Версия студии устарела…» и передаёт выбранное поведение в заголовке Studio-Version-Failed-Behavior.
  • Если Студия не передала свою версию, лицензия выдаётся без проверки.
  • Порог один для Студии Windows и Студии Linux.

Если задать только MinimumStudioVersion, поведение по умолчанию — 0: устаревшая Студия закроется без сообщения пользователю.

Операционные системы

Сервер

  • Службы публикуются как self-contained под win-x64 и linux-x64: отдельно ставить .NET не нужно.
  • Linux: службы оформлены как systemd-юниты (/opt/Primo/<Служба>), есть системный и пользовательский (rootless) варианты юнитов.
  • Docker-образы строятся на базе ubuntu:24.04 и Astra Linux (astra/ubi18:1.8.6); образы для Kubernetes — на astra/ubi17.

Машина робота

  • Агент есть для Windows и Linux.
  • На Linux агент сам знает команду графической сессии для Astra Linux (fly-wm), CentOS (gnome-session) и РЕД ОС (mate-session). Для других дистрибутивов, в том числе Ubuntu, задайте AgentCommands:Session вручную. Для Astra Linux 1.8 агент дополнительно запускает dbus-launch.

СУБД

Поддерживаются PostgreSQL и MS SQL Server: для каждой БД в коде есть два набора миграций.

В поставочных docker-compose используются образы postgres:14 и rabbitmq:3-management.
