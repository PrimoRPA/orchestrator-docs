Переход с root на работу без root

Применимо: 1.26.9Linux

На странице описан перевод действующей установки на Linux, в которой службы Оркестратора работают от root, на пользовательские юниты systemd. Начиная с поставки 1.26 работа от обычного пользователя — основной вариант.

Результатслужбы и агент работают от пользователя, запускаются после перезагрузки без его входа

Требования для работы без root и отличия юнитов — Установка служб → Linux: службы работают без root.

Службы и nginx

Шаги выполняются на сервере Оркестратора. Шаги 1–3 — под учётной записью с правом sudo, шаг 4 — под пользователем служб orch-user.

  1. Остановите и удалите системные юниты (повторите для каждой службы и для Primo.Orchestrator.Nginx): 
    sudo systemctl disable --now Primo.Orchestrator.WebApi
sudo rm /etc/systemd/system/Primo.Orchestrator.WebApi.service
sudo systemctl daemon-reload
    systemctl list-units 'Primo.Orchestrator.*' ничего не выводит
  2. Создайте пользователя служб (если его нет) и включите linger: 
    sudo useradd -m -s /bin/bash orch-user
sudo loginctl enable-linger orch-user
    loginctl show-user orch-user -p Linger выводит Linger=yes
  3. Назначьте пользователя владельцем каталогов служб, nginx (включая созданные от root logs и temp) и каталогов данных: 
    sudo chown -R orch-user:orch-user /opt/Primo
sudo chown -R orch-user:orch-user <каталоги данных из конфигов>
    find /opt/Primo ! -user orch-user ничего не выводит
  4. Откройте оболочку orch-user, установите пользовательские юниты и запустите службы в обычном порядке (MachineInfo, WebApi, остальные, nginx). Команды для WebApi повторите для каждой службы: 
    sudo su - orch-user
export XDG_RUNTIME_DIR=/run/user/$(id -u)
mkdir -p ~/.config/systemd/user
cp /opt/Primo/WebApi/Primo.Orchestrator.WebApi.user.service ~/.config/systemd/user/Primo.Orchestrator.WebApi.service
systemctl --user daemon-reload
systemctl --user enable --now Primo.Orchestrator.WebApi
    Юнит NuGet2 — /opt/Primo/NuGet2/Primo.Orchestrator.NuGet.user.service, nginx — Primo.Orchestrator.Nginx.user.service из поставки. systemctl --user list-units 'Primo.Orchestrator.*' — все active running; ps -eo user,cmd | grep Primo.Orchestrator показывает orch-user
  5. Перезагрузите сервер. службы запустились без входа orch-user в систему

Агент на машине робота

Агент переводится так же, на каждой машине робота:

  1. Остановите и удалите системный юнит /etc/systemd/system/Primo.Orchestrator.Agent.service.
  2. Включите linger для пользователя agent.
  3. Под пользователем agent установите Primo.Orchestrator.Agent.user.service из каталога агента в ~/.config/systemd/user/ и запустите службу. в UI4 на странице Настройки → Система → Машины роботов у машины в колонке Доступна обновляется дата

Возврат к работе от root

Обратный переход выполняется в обратном порядке: systemctl --user disable --now под пользователем, файлы *.service (без .user) — в /etc/systemd/system/, затем sudo systemctl enable --now. У nginx от root каталог www должен быть доступен всем на чтение.
